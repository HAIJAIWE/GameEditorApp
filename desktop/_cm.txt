1) P5 数量约束软检查（Python data_tab.py:370-432）
- 新增纯逻辑 src/shared/dataCountConstraint.ts：
  countLimitFieldNames（顺序照抄 Python 字面量 count / <type>_count / max_count /
  total_count）、resolveCountLimit（只认整数值或十进制整数字符串，非法值跳过继续试下一个
  字段）、findCountConstraint（只取第一个 data_type 命中的系统；命中但上限缺失/非法/<=0
  ⇒ 不约束）、exceedsCountConstraint（current >= limit 才拦，对应 Python current < limit
  才放行）、buildCountConstraintMessage（文案逐句对齐 QMessageBox 正文）。
- ceshu/CeshuDataPreview.tsx 用 findCountConstraint(chapters?.systems,
  activeEditor.data_type) 解析后作为 countConstraint 度下发给 DataEditorTab。
- DataEditorTab.handleCreate 在已满时先渲染行内确认横幅（.count-warning：继续创建/取消），
  确认后复用同一落盘路径。不引入任何原生对话框（Electron 渲染层无 window.prompt，
  window.confirm 也无法在 vitest 中断言）。

  与 Python 一致的只有：字段优先级 / 非法值 continue / <=0 不算约束。另有 4 处有意偏离，
  已逐例用 python -c 与 node -e 实测对照并存档到 docs/migration-audit.md 新增小节
  「E51 数量约束：对 Python 的有意偏离（逐例实测对照）」：
  (a) {count:true}：Python int(True)==1 ⇒ 上限 1；TS 跳过（上限字段出现布尔本身就是数据错误）。
  (b) '1_0' / '１２'：Python int() 宽松解析 ⇒ 10 / 12；TS 只认 ^[+-]?\d+$ ⇒ 跳过。
  (c) {count:3.0}：Python float 被跳过 ⇒ 无约束；TS 生效 —— JSON.parse 在 JS 里就是数字 3，
      与 3 无法区分，属语言层不可复现。
  (d) 系统缺 data_type：Python 严格 == 永不约束；TS 回退系统 key，与 computeEnabledEditors
      的 data_type ?? key 口径统一，避免「系统已启用、编辑器也显示了，却查不到约束」的静默漏判。
  前三处在策划书第五章的字段形态下不可达；(a)-(c) 已由单测钉住，不靠注释约定。
