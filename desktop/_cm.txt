1) 缺陷（既有，非 E51 引入）
E51 的渲染侧独立验证者报告：策划书右侧预览面板里条目行只有 160px，行的**几何中心
落在「删除」按钮上**，其 T5 用例第一次因此**误删**而非选中。

2) 实测根因（新增 preview/measure-row.mjs，用 document.elementFromPoint(行中心)
   判落点，不靠读 CSS 推理）
- .ceshu-preview .list-column 固定 flex: 0 0 200px，.list 左右各 20px 内边距 ⇒ 行 160px。
- 默认布局：删除钮 74.7px（整行 47%）、名称被压到 18.7px（「技能 1」文本需 40px，
  scrollWidth 40 > clientWidth 19 ⇒ 已截断）。
- document.elementFromPoint(行的几何中心) → ceshu-data-delete ⇒ 点中心即删除。

3) 修法（styles.css，全部限定在 .ceshu-preview .item-row 作用域）
- 删除钮文本包进 .btn-label 并在窄列 display:none ⇒ 收成 26px 图标；按钮本体与
  data-testid="ceshu-data-delete" 均保留（smoke.spec.ts:84 的
  getByTestId('ceshu-data-delete').click() 照旧可用），补 title/aria-label 保可访问性。
- .item-meta（8 位短 id）display:none 让位给名称；id 仍可由行 title 与右侧表单读到。
- .item-name { min-width: 64px } 兜底；删除钮 padding: 4px 6px。
- DataEditorTab.tsx：按钮文字包 <span class="btn-label">；行加 title="{name} | {id}"。

4) 效果（实测三档视口 wide-1440 / mid-1100 / narrow-900）

- 删除钮 74.7px → 26px
- elementFromPoint(行中心) → ceshu-data-item-row（= 选中该条目）
