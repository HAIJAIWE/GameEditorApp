## 2. ceshu:delete 补契约层删除确认

此前 `ceshu:delete` 复用 `ceshuGetInputSchema`，而它的 `confirmed` 是**云端超预算**标志
（v0.6 M5），与删除无关 ⇒ 删除操作在主进程侧**零守卫**。

渲染层 `CeshuHomePanel` 本来就有「删除「X」？此操作不可撤销」+ 确认/取消的 UX 二次确认；
这次补的是**契约层**，照 `data:clearAll` 的既有范式做：
- `schemasData` 新增 `ceshuDeleteInputSchema = { id, confirm: boolean }`（confirm 必填）
- `ipc.ts` 的 `ceshu:delete` req 改用 `CeshuDeleteInput`
- handler：`if (req.confirm !== true) throw new Error('删除策划书需要确认')`
- `CeshuHomePanel` 调用点传 `confirm: true`

负向探针：把调用点改回 `{ id }` ⇒ 立刻 `TS2345: '{ id: string; }' 不能赋给
'{ id: string; confirm: boolean; }'`（已验证后恢复）。⇒ 将来任何新调用点（agent skill /
CLI / 测试）漏传都会在**编译期**被拦下，而不是等到误删发生。
