# HTML 做游戏能做到什么程度？（2026 现状 + 我们单文件 demo 的天花板）

> 关键：**「Web 平台能做的游戏」≠「我们 `generateDemo` 单文件 demo 能做的游戏」**。
> 前者很大，后者很窄。分开看才不会被"HTML 什么都能做"误导。

## 一、Web 平台（用引擎）2026 能做到什么

**结论：Web 早就是"真游戏平台"了，不是玩具。**

- **WebGPU 已成熟**：W3C 标准，2026 年全球浏览器支持率**约 90%**（Firefox 147 于 2026-01 在 Apple Silicon Mac 全面启用）；PlayCanvas 等已支持 WebGPU + 计算着色器，同时兼容 WebGL2。
- **引擎齐全**：Three.js / Babylon.js / PlayCanvas / Cocos Creator / Unity WebGL / Godot Web(WASM)。
- **可做**：2D / 2.5D / 3D、多人（WebSocket/WebRTC）、上架（Steam 走 Electron、手机浏览器、小游戏平台、playable ads）。

**2026 一份 Web 3D 引擎横评（大致量级，供参考）**：

| 引擎 | 包体 | 冷启动 | 备注 |
|---|---|---|---|
| Three.js | ~200KB | 1–1.5s | 轻、需自己搭 |
| PlayCanvas | ~300KB | 1–1.5s | WebGL+WebGPU |
| Babylon.js | ~1.4MB | — | 配 Havok 可稳 60fps |
| Cocos Creator | 0.8–1.5MB | — | 国内小游戏生态强（主包 4MB 限） |
| Godot Web | 3MB+ | — | WASM，限制较多 |
| Unity WebGL | 5–8MB | 10–20s | 重，但生态最全 |

## 二、我们的「单文件 HTML demo」能做到什么（现实阶梯）

`generateDemo` 的产物是**单文件、无外部资源、无引擎**——所以天花板比上面低一大截：

**✅ 强（很适合）**
- 2D 玩法：卡牌、消除、放置/挂机、塔防、Roguelike、平台跳跃、解谜、文字冒险、回合制；
- 简单经营/SLG（小规模）、UI 驱动的游戏；
- **程序化图形**（用代码画，不依赖图片素材）——正好绕开"没有美术资产"。

**◐ 中（能做但不精）**
- 极简 3D（手写 WebGL 或非常轻的渲染）；
- 粒子、基础物理、简单动画。

**❌ 弱 / 做不了**
- 大型 3D、复杂物理/网络同步、大内容量；
- 依赖美术资产管线（模型/贴图/骨骼动画）；
- 移动端性能、主机/商店上架、多人稳定联机。

## 三、什么时候必须换引擎（判据）

出现下面任意一条，就该从"单文件 demo"升级到引擎（Unity/Unreal/Godot/Cocos）：

1. 需要**美术资产**（模型/贴图/骨骼动画）；
2. 需要**复杂 3D / 物理 / 网络同步**；
3. **内容量大**（几十关、上百角色）；
4. 要**上架**（Steam / 手机商店 / 主机 / 小游戏平台）；
5. 要**团队协作**、长期维护。

## 四、对我们的意义

- **demo = 层②「试板」**：目标不是"做好游戏"，而是"把核心循环跑起来，让人 30 秒判断值不值得做"；
- **正式开发 = 引擎工程**（不在 HTML）；
- **层③（数据表 / 岗位任务 / 机读包）= 从 demo 到引擎的桥**，我们已经有了。

所以 demo 生成器该瞄准的是：**"2D、程序化图形、核心循环可玩"**——这恰好是单文件 HTML 最擅长、也最够用来验证想法的区间。

## 五、更正与补充：HTML 能不能做 3D？「AI 生成 3D」又是什么？

**更正**：上一节说"单文件 demo 只能极简 3D"，指的是**我们的生成器**（无外部资源、单文件），**不是 HTML 的能力**。
**HTML/Web 完全能做 3D**：WebGL2 / WebGPU + Three.js（2026 约 11.6 万★）/ Babylon.js / PlayCanvas。
2026 已有浏览器 3D 平台跳跃、多人竞速、3D 象棋等；**Meta 开了 30 万美元悬赏「AI 生成的 Three.js 游戏」**，
**Kimi K3 也用 Three.js WebGPU 做了 AI 生成的 3D 探索游戏**。

**「AI 生成 3D」有三种，别混**：

| 类型 | 代表 | 产出 | 用什么"语言" |
|---|---|---|---|
| ① AI 生成 **3D 模型** | Meshy / Tripo3D / Rodin(混元) / Luma | **GLB / FBX / OBJ 模型文件** | **没有语言**——是资产文件 |
| ② AI 生成 **3D 游戏/场景** | Kimi K3、Meta 悬赏的 Three.js 游戏 | 能跑的场景/游戏 | Web=**JS+Three.js**；Unity=**C#**；Unreal=**C++** |
| ③ AI **世界模型** | Genie 3 / GameNGen | 神经生成的 3D 视觉/交互 | 不写代码（研究级） |

> 补充：AI 生成 3D 模型「现阶段只能当原型，正式项目交付还需人工修拓扑与细节」——所以它也是**原型/资产**，不是成品。

**所以"不知道用什么语言"的答案**：
- 如果是**模型** → 没有语言，是 GLB/FBX 这类资产文件；
- 如果是**游戏/场景** → 大概率 **JavaScript（Three.js）** 或 **C#（Unity）**。
