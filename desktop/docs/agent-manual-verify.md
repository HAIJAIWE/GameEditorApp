# 智能体对话面 · 手测清单（M0.5 / M1 / M2 / M2.5 / M3 + v1.6 模型校正 + v1.7 线格式修复）

> 为什么要有这份：`vitest` 覆盖的是**纯逻辑与装配**，e2e 覆盖的是**桩服务**（`tests/e2e/agent-brain-chat.spec.ts`）。
> 真正「接上活模型后是否好用」只有本机手测能得到——沙箱**没有 GUI、没有本地模型、没有云端 Key**，
> 下面每一条都**无法**由自动化替代。测完请把「失败项 + 现象」回填，不要只说「不行」。

---

## 0. 前置

| 项 | 命令 / 说明 |
|---|---|
| 起应用 | `cd desktop && npm run dev`（或装好后直接开应用） |
| 本地档模型 | `ollama pull qwen3:8b`，并确保 `ollama serve` 在跑 |
| 云端档 | 设置 → AI 模型服务 → 勾「启用 API」→ 服务商选 **DeepSeek** → 填 API Key → 模型确认是 **`deepseek-v4-pro`** |

> ⚠️ 本地档还需要环境变量 `MB_OLLAMA_MODEL`（数字员工对话面读它；设置面板的「AI 模型服务」对**本地**档不生效，这是 M0 有意留下的边界，M3 已让**云端**档读设置）。
>
> ⚠️ **v1.7 起云端档也能选 Qwen**（`https://dashscope.aliyuncs.com/compatible-mode/v1`，默认模型 `qwen3-max`）。
> 若在 A 段复现出 **HTTP 400 `InvalidParameter: input.tools.0.type must be one of ['function']`**，
> 说明线格式包装又被人改回去了（`brainService` 是唯一转换点，见设计文档 §5.5.14）——**这是回归，不是配置问题**。

## A. 云端档（默认主力）

| # | 操作 | 通过标准 | 失败长什么样 |
|---|---|---|---|
| A1 | 按上表配好 DeepSeek，**重启应用**（验证启动推送镜像） | 无需重进设置即可用 | 报「尚未配置 AI 服务」⇒ `llmBootstrap` 推送失败 |
| A2 | 数字员工面板问一句闲聊，如「你好」 | 正常回答；**底部出现「本次消耗 ☁ 云端 · N 轮 · M token · K ms」** | 显示「🖥 本地」⇒ 档位路由没生效 |
| A3 | 问一个**必须用工具**的：如「列出全部数据类型」 | 面板步骤区出现 `system.game_data` 步骤且**成功**；回答里是真实类型名 | 模型只回文字不调工具 ⇒ 工具面/提示词对不上 |
| A4 | 说「帮我新建 3 个角色：战士、法师、盗贼」 | 模型调用 `system.game_data`（应为 `batch_create`，**一次**调用建 3 条） | 分 3 次单条调用 ⇒ M2.5 批量动作没被选中（不致命，记下来） |
| A5 | 让它删一条数据 | 弹**危险操作确认**（`TOOL_RISK_MAP` 走 approvalBroker）；拒绝后数据**没变** | 没弹确认就删了 ⇒ 审批闸漏了（**严重**） |
| A6 | 换 **Qwen** 档（DashScope）：服务商选 Qwen → 填 Key → 模型应为 **`qwen3-max`**，再问 A3 那句 | 正常调工具；**不出现 HTTP 400** | 400 `input.tools.0.type must be one of ['function']` ⇒ **v1.7 线格式修复被改回去了**（回归） |
| A7 | 本地档（B3）**修完线格式后重测一次** | 4B/8B **真的会调工具** | 仍完全不用工具 ⇒ 这次才是真的模型能力问题（M2 的原结论需重估） |

## B. 本地档（保密 / 离线）

| # | 操作 | 通过标准 | 失败长什么样 |
|---|---|---|---|
| B1 | 设置 → 打开「🔒 保密模式」 | 服务商框变灰、回落 Ollama，提示「数据不出本机」 | — |
| B2 | 同一句「你好」 | 底部显示「🖥 本地」；能回答 | 报「未指定本地模型」⇒ `MB_OLLAMA_MODEL` 没设 |
| B3 | 同一句「列出全部数据类型」 | 看 4B/8B 是否仍会**用工具**（这是 M2 减提示词要验证的核心） | **完全不用工具、只编一段像模像样的答案** ⇒ 提示词仍太长（M2 的退化信号） |

## C. 终止闸（M0.5）

| # | 操作 | 通过标准 |
|---|---|---|
| C1 | 提一个需要很多轮的要求，如「把每个类型都列一遍，然后逐个统计条数」 | 最多 6 轮 / 8 次工具 / 120 秒后**停下并给部分结果**，底部出现「⏹ 已达…上限，以下是已完成的部分结果」 |
| C2 | 同 C1，但**不要**让它无限转 | 不允许出现「一直转、一直调同一个工具」的死循环 |

## D. 已知缺陷（**预期会看到，不用报**）

| 现象 | 说明 |
|---|---|
| **从没配过** AI（或启动推送失败）时，数字员工对话面**静默走本地 Ollama** | M3 把 `unconfigured` 映射成了本地。与 M0「不静默回落」相抵，**已知、待改**（建议改为引导去设置） |
| 云端档回答**不是逐字流式**，是一段一段蹦出来 | `openAiTransport` 本版**非流式**（`onChunk` 整段一次性回调）。本地档仍是逐字流 |
| 数字员工面板**没有工具勾选框** | DD-4 的「显式选择」协议与装配已就绪（`explicitTools`），UI 入口是独立项 |
| 云端档**没有花费护栏**（对话面） | M5 只护栏了策划书/数据域；对话面的预算门是独立项（M3 §5.5.13 范围判定 ⑤） |
