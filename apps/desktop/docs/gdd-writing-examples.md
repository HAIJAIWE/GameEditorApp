# 他们到底怎么写游戏设计文档？（6 个真实样本的「写法」拆解）

> 承接 `real-gdd-structure-comparison.md` / `gdd-china-vs-international.md`。这次重点是**写法（文体与组织）**，
> 不是"有哪些章"。6 个样本都公开可查。

## 一、样本一览

| # | 样本 | 年份/品类 | 它是什么 | 写法特征（一句话） |
|---|---|---|---|---|
| 1 | **Doom Bible** | 1992 FPS | 叙事/关卡圣经 + 媒体稿 | 分章讲故事、列武器/关卡；**数值基本不写**（护甲值写「?」） |
| 2 | **Scrapbots** | 2019 卡牌 | 规则书 | Setup→回合阶段→动作→伤害→胜负，**全是可执行规则** |
| 3 | **Cryptic** | 2019 社区 | 里程碑功能表 | `状态\|功能\|后端\|前端` + 发布日，**不写叙事** |
| 4 | **downflux** | 2020 RTS | 技术设计档案 | `client/server/fsm/network`，**没有玩家向 GDD** |
| 5 | **game-of-winter** | 2021 学生 | GDD 网站 | 摘要 / 玩法 / 机制 / 元素 / 资产，**分页网站** |
| 6 | **数值策划 Excel**（真实 SLG 项目） | 真实项目 | 数值表体系 | **树状多表 + 属性总表 + 公式总表**，数值全在表里 |
| 7 | **Cataclysm-DDA** | 活跃开源（13 万提交 / 1000+ 贡献者） | 贡献者设计规范 / lore | **分层 + 自动目录 + 交叉链接**，每条附「为什么」 |
| 8 | **0 A.D.** | 知名开源 RTS | wiki 设计文档 | **中心页 + 子页链接**，不是单文件 |
| 9 | **Diablo 1994 Pitch** | 1994 商业（暴雪发行） | 8 页发行简报 | **极短**：游戏设计 / 设定玩法 / 市场研发 / 进度表 |

## 二、逐个看「怎么写」

**1. Doom Bible —— 写「体验与内容」，不写「规格」**
`Section 4 Play Loop` 只有一句「New 3-D engine」；武器只写「minimum damage / more powerful」；
护甲值直接写「?」。它把力气全花在**剧情/角色/关卡**和**媒体稿**（定位、对标 Wolfenstein）。
→ 启示：**叙事型文档可以很"虚"，数值/规格另有人写。**

**2. Scrapbots —— 写「可执行规则」**
`Setup → Turn Phases → Actions（买/组件/资源/造机器人/攻击）→ Dealing Damage（溅射/摧毁/创伤）→ Winning`。
每一步都能照着玩：3 条道、每 10 点伤害一张创伤、20 张创伤结束。
→ 启示：**规则类文档 = 状态机 + 数值常量**，几乎没有形容词。

**3. Cryptic —— 写「里程碑清单」**
Pre-Alpha 1 的 GDD 就是一张表：`状态 | 功能 | 后端 | 前端` + `Release: 27.05.2019`。
→ 启示：**早期项目的"文档"可能就是一张功能表**，不写长文。

**4. downflux —— 写「技术架构」**
`design/client.md / fsm.md / network.md / server.md`。没有定位、没有玩法、没有关卡。
→ 启示：**有些"设计文档"其实是 TDD（技术设计），不是 GDD。**

**5. game-of-winter —— 写「网站分页」**
`index / summary / gameplay / mechanics / elements / assets` 六个 HTML 页。
→ 启示：**现代独立/学生项目把 GDD 做成 wiki/网站**，一页一节，而不是一个大 Word。

**6. 数值策划 Excel（最硬核，值得逐条学）**
一个真实 SLG 项目的完整数值表体系，写法是**树状多表**：

- **表分层**：`设计表`（各层设计数据）→ `数据表`（给程序读的接口）→ `数据表说明表`（规范）→ `枚举表`（分类）；
  首层一张「总表」定最核心体验参数，末层 3 张表，中间都是设计表。
- **单元格三态**：`参数`（独立关键值）/ `曲线`（趋势，2 列或 2 行）/ `矩阵`（枚举分布）；
  计算 = 参数+曲线→曲线、参数+矩阵→矩阵。
- **规范化表头**：表格名/系统名/类型 + `字段类型（功能/文案/美术/数值）` + `外键` + `字段说明` + `字段英文名` + `中文名` + `数据类型`。
- **唯一识别码**：`表格名_字段名`；每表有主键，字段有外键 → 可跳转、可查错。
- **两张总表**：`属性总表`（所有单位属性统一编号，如 100-137，可写语义表达式 `C01;100;10%`）、
  `公式总表`（900+ 行：公式怎么写、**值去哪取**、UI 显示什么、受哪些科技影响，还带**验错工具/输出区**）。
- **颜色约定**：灰色=计算得出、不可直接改；区分「原设计数据 / 计算数据」。
- **一键导出**：csv/json 给程序，SVN 提交，改一个数 → 导出 → 客户端/服务器，20 秒内看到反馈。
- **目标**：表是「**和程序的接口**」，测试也照它验 bug。

## 三、横向规律：他们「怎么写」的 6 条

1. **按系统/功能写，不按"一整份文档"写**——战斗、经济、背包各自成篇/成表。
2. **数值一律进表，不写散文**——参数/曲线/矩阵 + 说明表 + 枚举表；公式总表写「怎么算 + 去哪取」。
3. **写"给程序怎么读"**——字段英文名、类型、取值范围、取值位置、导出格式，而不是文学描述。
4. **可维护性靠编号/唯一码/颜色**——`表格名_字段名`、属性编号、灰色=计算值；否则表一大就乱。
5. **文体随品类变**：叙事(Doom) / 规则(Scrapbots) / 里程碑(Cryptic) / 技术(downflux) / 网站(game-of-winter) / 表(数值)。
   **没有统一文体，只有统一的"给谁看、要能执行"。**
6. **热门项目用 wiki/知识库，不是单文件**：中心页做导航、细节拆子页、靠交叉链接（Cataclysm-DDA、0 A.D. 都是这样）。
   **一份大 GDD 反而是小项目/老项目的做法。**

## 四、对「交给 AI 生成」的直接启示

- **别让 AI 写散文**：让它按「系统/功能」出**结构化条目**（规则用状态机、数值用表）。
- **数值类字段要 AI 输出成表**：参数/曲线/矩阵，并写清「取值来源」；断言必须**可复算**（对应我们的 `numeric_assertions`）。
- **机读层就是"给程序读的那份"**：我们的 `data_tables` / `ledger` / 公式类字段，正对应上面的"数据表/公式总表"。
- **任务清单**要 AI 输出成 checklist（岗位 × 章 × 字段），不是段落——这也印证了上一轮把导出做成"岗位任务清单"的方向。
- **长期大项目别硬塞进一个大文档**：**中心页 + 子页**（像 0 A.D. / Cataclysm-DDA）比一份 24 章 Word 更贴近真实热门项目。
  我们的「一页摘要 + 详细章节」其实就是"中心页 + 子页"的雏形，可以再往"按实体/系统拆页"演进。

## 五、热门项目怎么写（两份高活跃开源）

**7. Cataclysm-DDA —— 面向贡献者的「设计规范 / lore」**（`doc/design-balance-lore/technology.md`）
- **分层分类**：民用 → 军用 → 绝密 → 异星（按保密/先进程度）；
- **自动目录**（doctoc 生成，标注「别手改」）+ **大量交叉链接**（指向 lore-background / lore-factions）；
- **每条设定都附「为什么」**：既讲世界观原因，也讲**游戏设计原因**（平衡 / 掉落 / 玩法）；
- **直接对贡献者说话**（「设计高科技武器先问为什么量产」）——本质是**贡献者规范**，不是纯故事；
- 口语化、详略不均、明确标「施工中」（Yrax 段只有标题）；
- **没有表格、数字极少且定性**（「降低至少一个数量级」），用一条 **ASCII 等级标尺**代替数值。

**8. 0 A.D. —— wiki 中心页 + 子页**（`Design_Document`，trac wiki v2.1，CC-by-sa）
- **中心页是导航**：Licensing/Disclaimer → Background（Vision / War Story / Territories）→ 12 个可玩文明 → 其他文明 → Lists（Entities: Nature/Player、Structures、Units、Maps、Traits、Actions）；
- 真正的细节全在**子页**（`Civ:Athenians`、`List:Entities:...`、`XML.Entity.Traits.*`）；
- 单独的 **`0 A.D. - The Vision`** 页承载愿景；
- 开头有**免责声明**（as-is，最终可能不同）。

**9. Diablo 1994 Pitch —— 8 页打动发行商**（据知乎对原扫描件的翻译/解析，**二手来源**）
- 全 **8 页**（含封面与 1 页插图）：封面（Condor / Copyright 1994）→ **游戏设计**（回合制 RPG、随机地牢、45° 视角、多人）→ **设定与核心玩法**（中世纪、战士/盗贼/法师、属性、城镇地图、左右键操作、地图迷雾）→ **市场与研发**（扩展包/DLC 雏形：$4.95、收银台摆放、收藏卡；11 人团队、1 年工期、SVGA 640×480、16 种怪物、每个死亡动画 50 帧）→ **开发进度表**。
- 最终 15 人、30 万美元、不到两年做出；这份「简陋 8 页纸」就是打动暴雪的全部。
- 启示：**商业 pitch 极短，但含「市场 + 团队 + 排期」**——短 ≠ 不完整，是「只写能说服人的」。

> 附：GTA 1（1995）原版设计文档 PDF 已下载，但为**扫描件**（12 页仅抽出 11 字符），无法可靠解读，故不列结论。

→ **热门项目的共同点：不是一份大文档，而是一个 wiki / 知识库**——中心页做导航，细节拆子页，靠交叉链接串起来。
