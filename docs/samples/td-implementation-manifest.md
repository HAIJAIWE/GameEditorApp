# 实现契约（构建清单）— 烬土守望

> 游戏类型：塔防｜档位：full

## 一、构建顺序（垂直切片优先，非文档顺序）
1. **数据层：实体与字段** — 按 2 个已启用系统建实体与字段
2. **状态机骨架** — 按 6 条转移实现状态机（含异常路径）
3. **核心循环跑通一局** — 按 5 步核心循环做出最小可玩闭环；内容：4 个核心特性 / 3 个首关
4. **数值约束落地** — 实现时守住 5 条数值约束（公式/平衡/断言）
5. **验收** — 按 4 条验收标准判定完成

## 二、核心循环
布置炮塔 → 开始波次 → 击杀获资源 → 升级/加塔 → 抵御更强波次
- 布防
- 开始波次
- 击杀获资源
- 升级炮塔
- 抵御下一波

## 四、系统模块（数据实体）
### 战斗（battle）
- damage_formula: 炮塔伤害 = 攻击 − 敌人护甲 × 0.5
- combat_pace: 波次制（间隔布防）
- ai_behavior: 沿固定路径直行，不攻击
### 经济（economy）
- currency_types: 废土币（唯一）
- sink_mechanisms: 建塔 / 升级炮塔

## 六、数值约束
- 【数值公式·要点】炮塔伤害 = 攻击 − 敌人护甲 × 0.5
- 【数值公式·要点】敌人血量 = 20 × 波次^1.2
- 【数值公式·要点】击杀伤收益 = 3 + 波次
- 【平衡原则】资源产出略低于建塔消耗，逼玩家取舍
- 【平衡原则】越靠后的波次护甲越高

## 七、验收标准
- [ ] 能建塔、升级并撑过 3 波不崩（来源：MVP 里程碑：α 切片）
- [ ] 5 名测试者各通关 1 关（来源：MVP 里程碑：β 内容）
- [ ] 核心循环（布防→波次→资源→升级）可完整跑通（来源：QA 验收准则）
- [ ] 无阻断性 bug（来源：QA 验收准则）

## 八、表现基线（通用最小手感，非文档派生）
> 通用最小表现基线（非文档派生，作为可玩性下限；成品需美术/音频专项打磨）
- 受击：目标闪红 + 轻微击退，给出「打中了」的即时反馈
- 命中：60–100ms 顿帧 + 伤害飘字，避免无声无息掉血
- 技能：有施法前摇与冷却，不瞬发连按
- 胜负：结算面板明确胜/负与获得，可一键再战
- 操作：首局 3 分钟内可发现全部核心操作，无需读文档
