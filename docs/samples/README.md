# 文档样本目录

这里放「专业文档生成团队」（检索 → 生成 → 审核 → 修订）的**实跑产物**，
用途有两个：① 验证该工作流的真实质量；② 作为本项目对应章节的字段级参考。

## ch16-accessibility-sample.md

- **题目**：移动端叙事解谜《拾光》的「可访问性与本地化」章（示例项目，非真实项目）
- **对应本项目章节**：第 ⑯ 章 `accessibility`
- **流程**：苏寻源检索 → 支笔生生成 → 严审之审核（首轮 REVISE，5 项必须改）→ 修订 → 主理人汇编
- **产物规模**：33 条验收项（V8/A7/M8/C4/L6），6 个不可豁免阻断项，12 个待填数据点

### 这次跑出来的三条经验

1. **审核真的会打回**，首轮 5 条里有 2 条是「两句话互相矛盾」这种真问题；
2. **修订会引入回归**：二稿重排编号时把「拖拽替代」这条阻断项弄丢了，只跑一轮审核发现不了；
3. **引用映射最容易错**：模型能背出标准编号，但会把「哪条对应哪个要求」搞错，
   这类错误只有懂 WCAG 的人能抓——所以引用编号必须人工过一遍。

### 对本项目的直接产出

`accessibility.acceptance_checks` 字段（检查项 / 依据 / 判定方法 / 责任角色 / 阻断）就是
从这份样本收敛出来的：原章 10 个字段全是描述性文字，没有任何一处能承接验收动作。
该字段按「补字段一律 optional」加，老文档完成度不受影响。
