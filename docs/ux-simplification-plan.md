## 一、能力盘点（先明确哪些是强项，方案不动它们）

一屏之内同时具备：结构化策划书编辑（分章 + 字段级校验 + AI 单章/整章生成）、可视化数据编辑（列表 + 动态表单 + 参考策划/AI 生成/关联）、AI 工作区、多库切换。屏外还有：13 类数据类型、18 章 GDD 校验与评分、6 种导出、属性公式引擎、自动保存/撤销重做。

**判断**：能力密度高于一般表格工具，问题在「怎么找到它」，不在「有没有」。

## 二、问题清单（带证据）

### P1 数据编辑没有自己的家，是「寄居」状态

同一个「编辑游戏数据」有 3 条入口路径，且互不一致：

| 入口 | 位置 | 现状 |
|---|---|---|
| 策划书编辑器 → 预览面板 | `ui/ceshu/preview_panel.py:159-160` 每次按需 `DataEditorTab(data_type, self._data_manager, parent=self)` | **可用**（用户截图里正在用的就是它） |
| TabManager 的数据标签 | `ui/tab_manager.py:175-187` 创建 `DataEditorTab(data_type, ...)`（无 parent） | 游离、未加入任何布局；`deferred_switch_tab()`（`:201-211`）里 `_center_stack.indexOf(tab) >= 0` 恒为假 → 实际不可达，只打 warning |
| 快速入门页的快捷创建卡 / 数据概览 | `ui/widgets/home_widget.py`（本轮修复后仅在「帮助 → 快速入门」窗口里可见） | 概览卡为纯展示，点击无反应 |

**代价**：新用户第一屏是策划书，找不到「配数据」；老用户要在两类界面间来回切换心智。

### P2 数据面板在窄容器里塌陷（截图里肉眼可见）

`ui/data_tab.py:75-85` 的 splitter 只设了 `setStretchFactor(0, 1)/(1, 2)`，**没有给左列（搜索 + 数据列表）设最小宽度**。实测（offscreen，`DataEditorTab` 直接 resize）：

```
容器宽 1200 → 列表列 187px | 表单列 999px | 列表最小宽 0
容器宽  900 → 列表列 140px | 表单列 746px | 列表最小宽 0
容器宽  700 → 列表列  80px | 表单列 706px | 列表最小宽 0   ← 塌陷
容器宽  520 → 列表列  80px | 表单列 706px | 列表最小宽 0
容器宽  400 → 列表列  80px | 表单列 706px | 列表最小宽 0   ← 内容宽 786px > 容器，溢出
```

- 列表列最小宽 `0`，表单列的固有最小宽约 **706px**，两者相争时列表先塌陷。
- 空状态文案「暂无数据，点击「新建」按钮添加」需要 **180px**，而列表只剩 **80px** → 被切成「击「新」（截图中 `x≈595, y≈658` 处那半截字）。
- 结论：这是「无最小宽度保护 + 表单最小宽过大」导致的，不是数据问题。

### P3 操作带过多，层级重叠

一屏内可见 5 条操作带：菜单栏 → 顶部库条（当前库/计数/设置/智能体/AI 助手）→ 第二行（返回/版本 + 保存/校验/AI 生成/AI 整章/AI 数据/更多/导出）→ 数据区底部一排 8 个（新建/保存/删除/复制/编辑类型/参考策划/AI生成/关联）→ 右栏 AI 面板自带输入条。找功能靠扫视，且「保存」出现两次（第二行与数据区底部），语义还不完全一样（策划书 vs 数据条目）。

### P4 一致性小刺

- **字段 AI 钮不统一**：紫色圆钮出现在「游戏名称/一句话定位/特色标签/设计愿景/次要用户/差异化优势/商业模式」，但「平台/文档状态/保密级别」没有。实现落在 `ui/ceshu/ai_field_button.py` + `ui/ceshu/chapter_forms/_common.py:123`，是否出现取决于字段是否声明 `ai_path`——用户视角看不出规则。
- **留白失衡**：数据区下半屏空白（表单只占上半屏），而左列已被压到 80px——空间分配反了。
- **文案长度未按容器裁剪**：同 P2，空状态、提示类文案没有省略号/换行策略。

## 三、三档方案

### A. 布局韧性（改动小、风险低、立刻可见）

| 改造点 | 文件 | 做法 |
|---|---|---|
| A1 列表列最小宽度 | `ui/data_tab.py:75-85` | 左列 `setMinimumWidth(200)`（或按字号算 180–220），并给 splitter `setSizes` 记忆比例（可复用 `windows_state` 的方式）；容器再窄时让表单列先缩 |
| A2 表单列可缩 | `ui/widgets/dynamic_form.py`（表单控件） | 给字段控件设 `setMinimumWidth(0)` + 长标签省略，降低 706px 固有最小宽 |
| A3 空状态/提示文案防截断 | `ui/widgets/virtual_list.py`、`ui/data_tab.py:138` | 文案缩短（如「暂无数据，点「新建」添加」）+ `elidedText` 或自动换行 |
| A4 字段 AI 钮统一 | `ui/ceshu/ai_field_button.py`、`chapter_forms/_common.py:123` | 二选一：(a) 所有文本字段都挂钮；(b) 去掉散落圆钮，改为字段聚焦时在行内出现一个统一的「AI」入口 |
| A5 断点自检 | `tests/unit/` 新增 | 断言「容器 520px 时列表列 ≥ 180px 且不溢出」，把 P2 变成回归测试 |

**预期**：截图里的塌陷列、半截文案消失；数据区空间分配合理。
**风险**：低——纯布局参数 + 文案；不触碰业务逻辑。
**验证**：offscreen 宽度扫描（本次已写成脚本，可固化为测试）+ GUI 复验 520/700/900/1200 四档宽度。

### B. 流程收敛（中等，需先定产品意图）

| 改造点 | 文件 | 做法 |
|---|---|---|
| B1 给「数据」一个正式容器 | `ui/layout_builder.py`、`ui/tab_manager.py` | 把数据编辑从「策划书预览面板」提升为独立页（放 `_center_stack`），预览面板改为「引用值只读预览」，避免同一份 UI 两处语义 |
| B2 明确入口 | `ui/ceshu/home_view.py`、顶部工具条 | 增加「数据」入口（或让数据概览卡可点击跳转）；`tab_mgr.deferred_switch_tab` 修好，AI 技能「切到某类型标签页」才真正可用 |
| B3 按钮分组 | `ui/data_tab.py`（底部 8 键）、`ui/ceshu/editor_view*` | 按「数据操作 / AI / 关联」分组，低频项收进「更多 ▾」；消除重复「保存」歧义（策划书保存 vs 数据保存改名或合并） |

**预期**：一条主线——策划书=文档、数据=表格；AI 也能可靠切页。
**风险**：中——涉及布局归属与既有交互习惯，需要一次完整回归。

### C. 首页职责重构（较大）

首次进入二选一：「写策划书 / 配数据」，两套首页各自聚焦。素材已具备：`ui/widgets/home_widget.py`（快速入门 + 数据概览 + 快捷创建）本轮刚从「游离悬挂」状态救出并修好布局，正好可作为「数据侧首页」的底子；策划书侧已有 `ui/ceshu/home_view.py`。
**风险**：高（产品方向决策 + 影响所有用户的首屏路径），建议在 A/B 落地后再评估。
