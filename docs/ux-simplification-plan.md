# 可视化界面信息架构与简化方案

> 状态：**历史方案 + 决策记录**。第一～四节写于「无左侧栏 / 单栈 / 互斥浮层」阶段，
> 该布局描述已被后续演进覆盖；**当前 UI 一律以代码与实时窗口为准**（见第〇节复核）。
> 第五节三处待评估已于 2026-11-04 定稿，不再列为开放项。
> 结论先行：**能力不缺，缺的是一条主线**——需要「收敛信息架构」，不需要砍功能。

## 〇、现役信息架构（2026-11-04 复核）

`MenuBar`（顶部）+ 三段式 `Sidebar`（左：新建策划书 / 策划书 / 插件中心 / 关系图 / 高级搜索 / 更多，可折叠）
+ `mainView` 插件页签（策划书 / 数据编辑 / 技术设计 / 代码编辑 / 浏览器 / 会话）
+ `AiDock` 常驻智能体停靠栏 + 底部状态栏（版本 / 类型数 / SQLite 路径 / 语言 / 主题快切）。

策划书首页是 `mainView`「策划书」页签的默认视图，2026-11-04 起为 dsh「开始」引导屏形态：
56px 罗盘水印 + 单列 380px 胶囊门（4 个创建门带 11px 描述 + 1 个库锚点，垂直居中一屏），
文档管理能力（最近 / 搜索 / 卡片网格 / 重命名 / 复制 / 派生 / 删除）滚动下沉到折叠线以下、DOM 常驻。
胶囊内容来自 `packages/shared/src/ceshu/homeActions.ts` 注册表，
并开放 `ceshu.home.guide` chain 替换缝供插件整体接管引导体。

> 注意：第一～四节的「无左侧栏」「单栈」等表述仅作决策沿革保留，**不要据此判断当前布局**。
> 判断现役形态请读 `App.tsx` / `Sidebar.tsx` / `plugins/panels/coreViewsPlugin.tsx` / `CeshuHomePanel.tsx`。

## 一、与 早期版本的关键差异（刻意保留/调整）

| 维度 | 早期版本 | TS 版 |
|---|---|---|
| 侧栏 | 有类型列表侧栏 | 下线（能力改走菜单栏，避免与既有交互习惯冲突；`TypeVisibilityPanel` 一并下线） |
| 数据编辑位置 | 寄居在策划书预览面板 / 游离 Tab / 概览卡三处不一致 | 统一为编辑器内嵌的 `DataEditorTab`，经「快速入门 → 去设计游戏数据」或首页「第二步」进入 |
| 主栈 | `_center_stack` 多页 | 单栈：首页 ↔ 编辑器，默认落首页 |
| AI | 面板内输入条 | 右侧常驻 `DigitalPanel` 停靠栏（单一实例） |
| 浮层 | QDialog | div 浮层，`Esc` 关闭、互斥 |
| 主题 | 事件总线实时切 10 套 | `shared/theme` + localStorage，4 档（深/浅/暖调/暗夜） |
| 快捷键 | 含 `Ctrl+S` 整文档保存 | 仅 `Ctrl+Z` 撤销 / `Ctrl+Y` 重做（章节草稿级保存刻意不做整文档保存，故不广告无反应的键） |

## 二、编辑器工具栏收敛

策划书编辑器与数据编辑器的操作带经「**更多 ▸**」收纳：高频操作（新建/保存/删除/复制/AI生成）平铺，低频（编辑当前类型字段结构、查看引用、关联等）收进「更多 ▸」下拉，消除重复与层级重叠。

## 三、布局韧性

- 数据区 `DataEditorTab` 列表列设最小宽度，容器变窄时表单列先缩（不再塌陷到 80px）。
- 空状态文案缩短并防截断（如「暂无数据，点「新建」添加」）。
- 菜单项永不留「点了没反应」的占位项；无可用类型时给明确引导而非灰死。

## 四、设计原则（落地即遵循）

1. 收敛信息架构，不砍功能。
2. 单栈 + 互斥浮层，避免多入口语义冲突。
3. 无左侧栏，能力集中到菜单栏右侧角部件（库选择 + 设置/智能体/AI）。
4. 渲染层零 Node 权限，所有原生能力经 `window.mbApi` 由主进程代劳（文件选择、图片读取、密钥）。
5. 切换库整页重载，保证所有视图从新库重新拉取。

## 五、已定稿（2026-11-04，不再列为开放项）

1. **不回到「二选一首页」** —— 维持「主线：先写好策划书，再设计数据」，数据设计是
   策划书之后的同一工作区阶段，不做并列首页。
   实证：`CeshuHomePanel` 已改造为 dsh「开始」引导屏，胶囊动作全部是
   「新建 / 复制 / 复刻 / 导入」类创建门，与「写策划书 / 配数据」的二选一互斥；
   「数据编辑」是 `mainView` 的独立页签，本就是同一工作区的后续阶段。
2. **字段 AI 钮统一方向** —— 维持按字段契约显示，既不「全挂」也不收成单一入口。
   实证：`ChapterForm.tsx:475` 按 `meta.aiDraftable` 决定按钮是否可用；
   `!aiDraftable` 的字段显示「人定」徽章（`:487`）而非隐藏按钮 —— 既避免对不该由 AI
   起草的字段误操作，又保留可见性。契约体系是 `aiHint` / `reviewHint` / `aiDraftable`
   （`ai_path` 是早期叫法，代码中已不存在），覆盖率由 `ceshuFieldMeta.test.ts` 守卫。
3. **「开始」屏位置：不搬运到右侧栏 tab** —— 维持当前 `mainView` 页签内。
   依据：dsh 的 guide 确实是 `sidebar.right.pane.tab`，但墨白 `mainView` 页签在布局分区上
   已占据同一位置；用户最初明确要求对齐的是 **UI 界面观感而非布局方式**，当前
   「罗盘 + 单列胶囊」首屏已与 dsh guide 视觉一致。搬运会改动产品信息架构、破坏
   `home-*` 系列 e2e 与既有用户习惯，收益只剩命名对齐。插件整体接管能力已由
   `ceshu.home.guide` chain 替换缝提供，无需靠搬运获得。

## 六、dsh UI 对齐结论（2026-11-04）

- 真值来源：`deepseek-harness-master/.../ui-sidebar-right/src/client/tabs/guide/GuideBody.tsx`
  + `GuideBody.module.css`（**不是** `apps/desktop/src/client/welcome*.tsx`，那是 OAuth 登录窗）。
- 规格：单列 380px 胶囊 / R20 / 0.5px 发丝边 / min-height 56px / 26px 不染色图标 /
  14px 常规字 / hover 只换背景；56px 罗盘水印；整屏零可见文字；`MAX_DESCRIBED_ENTRIES=4`。
- 已对齐：令牌层（`--radius-*` 六档、`--border-card/strong`、`--watermark-ink`、
  `--elevation-ink-*` / `--mask-*`、`corner-shape: superellipse(1.5)`）、引导屏形态、
  胶囊注册表与 chain 替换缝、样式守卫 `apps/desktop/tests/unit/styleRatchet.test.ts`（8 项全硬约束）。
- 有意差异：dsh 的极淡 elevation 三件套与 `MenuSurface` 材质未照搬（会造成视觉倒退），
  理由见守卫文件头「诚实边界」。
