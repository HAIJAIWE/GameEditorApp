# 可视化界面信息架构与简化方案

> 状态：**当前现役形态**（TypeScript + Electron 版，承载自 早期版本已落地的「收敛信息架构、不砍功能」路线）。
> 依据：Electron 渲染层实际组件（`App.tsx` / `MenuBar` / `CeshuHomePanel` / `CeshuView` / `DigitalPanel`）+ 全仓迁移设计文档。
> 结论先行：**能力不缺，缺的是一条主线**——需要「收敛信息架构」，不需要砍功能。

## 〇、现役信息架构（一句话）

无左侧栏；顶部菜单栏承载全部能力；中央是**单栈**（策划书首页卡片 ↔ 策划书编辑器，编辑器内嵌常驻数据预览面板）；右侧 `.ai-dock` 常驻智能体停靠栏；底部状态栏常驻（版本 / 类型数 / SQLite 路径 / 主题快切 / 快捷键提示）。其余能力（字段结构、属性系统、统计、搜索、对比、备份、生图、批量、引用、关系图、预览、快捷键、关于、清空、设置、清理图片、关键词模板、智能体能力、属性图表、快速入门）以**互斥浮层**承载，同时最多渲染一个。

## 一、与 早期版本的关键差异（刻意保留/调整）

| 维度 | 早期版本 | TS 版 |
|---|---|---|
| 侧栏 | 有类型列表侧栏 | 下线（能力改走菜单栏，避免与既有交互习惯冲突；`TypeVisibilityPanel` 一并下线） |
| 数据编辑位置 | 寄居在策划书预览面板 / 游离 Tab / 概览卡三处不一致 | 统一为编辑器内嵌的 `DataEditorTab`，经「快速入门 → 去设计游戏数据」或首页「第二步」进入 |
| 主栈 | `_center_stack` 多页 | 单栈：首页 ↔ 编辑器，默认落首页 |
| AI | 面板内输入条 | 右侧常驻 `DigitalPanel` 停靠栏（单一实例） |
| 浮层 | QDialog | div 浮层，`Esc` 关闭、互斥 |
| 主题 | 事件总线实时切 10 套 | `shared/theme` + localStorage，4 档（深/浅/暖调/暗夜） |
| 快捷键 | 含 `Ctrl+S` 整文档保存 | 仅 `Ctrl+Z` 撤销 / `Ctrl+Y` 重做（章节草稿级保存刻意不做整文档保存，故不广告无反应的键） |

## 二、编辑器工具栏收敛

策划书编辑器与数据编辑器的操作带经「**更多 ▸**」收纳：高频操作（新建/保存/删除/复制/AI生成）平铺，低频（编辑当前类型字段结构、查看引用、关联等）收进「更多 ▸」下拉，消除重复与层级重叠。

## 三、布局韧性

- 数据区 `DataEditorTab` 列表列设最小宽度，容器变窄时表单列先缩（不再塌陷到 80px）。
- 空状态文案缩短并防截断（如「暂无数据，点「新建」添加」）。
- 菜单项永不留「点了没反应」的占位项；无可用类型时给明确引导而非灰死。

## 四、设计原则（落地即遵循）

1. 收敛信息架构，不砍功能。
2. 单栈 + 互斥浮层，避免多入口语义冲突。
3. 无左侧栏，能力集中到菜单栏右侧角部件（库选择 + 设置/智能体/AI）。
4. 渲染层零 Node 权限，所有原生能力经 `window.mbApi` 由主进程代劳（文件选择、图片读取、密钥）。
5. 切换库整页重载，保证所有视图从新库重新拉取。

## 五、待评估（产品方向确定后再做）

- 是否要回到「二选一首页」（写策划书 / 配数据）—— 当前决策是「主线：先写好策划书，再设计数据」，数据设计是策划书之后的同一工作区阶段，不做并列首页。
- 字段 AI 钮统一方向（全挂 vs 收成统一入口）—— 当前按字段是否声明 `ai_path` 出现，行为已稳定。
