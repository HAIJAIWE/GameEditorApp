## C. 跨语言频次（用于判断）

| 章节 | 中文出现 | 英文出现 | 结论 |
|---|---|---|---|
| 背景/上下文 | 高 | 高 | 必留 |
| 目标与非目标 | 中 | 高 | 中文常缺"非目标"，应补 |
| 方案/设计本体 | 高 | 高 | 必留 |
| 替代方案与被否理由 | 低 | 高 | **中文最大缺口，应补** |
| 风险/取舍 | 中 | 高 | 必留 |
| 测试/验收 | 高（国标） | 中 | 中文更强 |
| 发布/回滚/迁移 | 中 | 高 | 应补"回滚/版本偏差" |
| 横切关注点 | 低 | 高 | **应补** |
| 术语表 | 低 | 中 | 可选 |
| 立项/可行性 | 高（国标） | 低 | 中文特色，可作可选 |
| 概要/详细设计分层 | 高（国标） | 中 | 中文特色，可作可选 |

## D. 对章表的判断（供架构讨论）

1. **不存在"标准章数"**：中英都是"核心 + 阶段/可选"。
2. **中文强在"阶段交付物"**（立项/概设/详设/测试/上线/复盘），**英文强在"决策质量"**（非目标/替代方案/横切/回滚）。
3. 建议章表 = **英文的决策骨架 + 中文的阶段可选**：
   - 核心 9–12 章：背景、目标与非目标、方案设计、数据与接口、替代方案、横切关注点、质量属性、测试验收、发布回滚、风险取舍。
   - 可选模块：立项/可行性、概要-详细设计分层、数据库设计、运维手册、复盘、AI 模型层。
4. 游戏侧沿用 gdad 的 7 节骨架 + 16 类文档的可选项（Pitch/Art Bible/Story Bible/TDD/内容清单/优先级/复盘）。

## E. 数据局限（必须写清）

- 中文 50 条中约 15 条是"同类换标题"，独立结构约 35；英文 50 条约 40 独立（ADR 13 个算 1 类）。
- 中文权威公开模板稀缺（多为文库/CSDN 转存），部分分节来自国标/行业常识而非原文抓取。
- 未覆盖：日韩/欧洲企业模板、各公司内部真实模板（不公开）。
- 结论用于**方向判断**足够；若要做"最终定稿章表"，建议再针对 2–3 个目标行业（如 SaaS / 游戏 / AI 产品）各取 5 份真实项目文档核对。
