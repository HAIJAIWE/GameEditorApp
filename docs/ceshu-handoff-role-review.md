# 交接文档的角色评审：十个岗位看同一套设计文档，会指出什么

> 日期：2026-10-27
> 方法：以 10 个岗位的视角逐份读交接包（6 卷 / 21–26 份文档），每个岗位只关心自己那几份，
> 指出「这份文档不足以让我开工」的地方，并列出它对应的开发物（代码 / 配置 / 资源 / 用例）。
> 结论按 P0/P1 排序在最后。

> **2026-10-28 更新**：评审时 P1 #8（结局达成条件）/ #10（性能测量方法）的 schema 已先行升级，本次补完模板与渲染；P0 #3（伤害公式两处冲突）已修复——`numeric.core_formulas` 不再重写伤害公式、只引用战斗章。详见 overview.md 第十轮。

---

## 0. 评审团与各自的关注点

| 角色 | 主要读的文档 | 只关心一件事 |
|---|---|---|
| 制作人 / 主策 | 范围与平台、核心循环 | 做不做、先做什么、什么算完成 |
| 系统策划 | 状态机、核心循环、装备/技能/经济 | 规则是否闭合，有没有自相矛盾 |
| 数值策划 | 数值参数与断言、战斗公式、成长/经济 | 能不能复算，有没有支配解 |
| 关卡 / 内容策划 | 关卡配置表、难度曲线、敌人与 Boss | 加一关要不要改代码 |
| 叙事策划 | 剧情分支与结局、世界观 | 分支有没有代价，结局是否可达 |
| 技术负责人 / 程序 | 引擎与技术栈、数据表、状态机、存档 | 数据从哪来、状态怎么切、档怎么兼容 |
| 美术 | 敌人与 Boss、地图与兴趣点、界面 | 要出多少资源、什么规格 |
| 音频 | （无专属文档） | 什么时候播什么音、并发上限 |
| 测试 | 反馈与可用性、性能预算、验收 | 怎么判过、怎么判不过 |
| 运营 / 本地化 | 埋点与指标、本地化与无障碍、抽卡 | 上线后看什么数、卖到哪些地区 |

## 1. 制作人 / 主策：「范围没写死，后面全是返工」

**看到的问题**
- `meta.non_goals`（范围与非目标）在样例里是空的——这是唯一能挡住「实现方自己加需求」的字段。
- MVP 范围写的是「核心战斗 + 1 关卡 + 主线第一章」，但 `mvp.cut_features` 里又列了「多人联机 / PVP / 外观」，
  而 `monetization` 章仍在规划月卡/战令/648——**MVP 范围和商业化范围没对齐**。
- `mvp.milestones` 与 `tech.milestones` 的时间点不一致（校验里能报出来，但没人看）。

**要补什么**：`meta.non_goals` 至少 3 条；MVP 里程碑与技术里程碑只留一处、另一处引用。

**对应开发物**：无（这是决策，但它决定后面 20 份文档做不做）。

---

## 2. 系统策划：「规则不闭合，实现只能猜」

**看到的问题**
- **同一件事两处定义且互相冲突**：第五章伤害公式 `(攻击 × 倍率 − 防御 × 0.5) × …`，
  第七章又是 `(攻击 − 防御 × 0.6) × 倍率 × …`。系数与乘法顺序都不同。
- `gameplay.state_machine` 是骨架主干，但默认文档里是空的——没有状态机，程序只能自己编一个。
- **词条（affix）没有独立结构**：`systems.equipment` 只有「套装/镶嵌/附魔」三个开关 + 强化上限，
  词条的**生成权重、数量上限、数值来源**都没地方写。
- 系统配置是「开关 + 上限」，但**系统之间的依赖**（装备强化消耗经济、技能升级消耗材料）没有表达。

**要补什么**：公式只留一处（其余引用）；状态机写实；词条用一张 `pipeList`（词条|类型|数值范围|权重|上限）。

**对应开发物**：`gameplay` 状态机代码、系统模块、词条生成器（需要新增字段，目前**没有**）。

---

## 3. 数值策划：「能写公式，但算不出数」

**看到的问题**
- `numeric.numeric_parameters` 在样例里是**空的**——没有参数表，公式里的「攻击/防御/倍率」全是符号。
- 缺等级上限、初始属性、每级成长值；`经验需求 = 80 × 等级^1.5` 有公式但没有上限与节奏目标。
- `numeric_assertions` 结构很好（断言|表达式|期望|容差|接受条件），但空着——**没有断言就没有验收**。
- 成长曲线只写「线性 + 软上限」「幂函数 1.5」，没有具体点。

**要补什么**：参数表 10–20 行（含合法范围）；3–5 条断言；曲线给 3 个关键点。

**对应开发物**：`RULES` 常量表、数值复算脚本（`contract.json` 里已有断言位）。

---

## 4. 关卡 / 内容策划：「加一关还要改代码」

**看到的问题**
- 本轮已补 `level_design.level_table`（关卡|敌人编队|奖励|难度系数|解锁条件），但：
  - **奖励是自由文本**（`gold×20`），没有指向数据表的 id，程序解析不了；
  - 敌人编队同样没有 id 约束（`slime×2` 是自造名）；
  - 缺**波次/刷新点**这类塔防与防守玩法的必备列。
- `content_estimate` 只有「阶段|数量|时长|依据」，与 `level_table` 的行数没有交叉校验（说 12 关，表里只有 3 行）。

**要补什么**：奖励与敌人改成「id×数量」；表行数 ≤ 内容量估算；塔防/防守品类补「波次与塔位」（本轮已加文档）。

**对应开发物**：关卡加载器、刷怪配置（读 `data/snapshot.json`）。

---

## 5. 叙事策划：「分支只有名字，没有条件」

**看到的问题**
- `story.branch_endings` 是 `stringList`（「正道结局：剑斩天道」），**没有达成条件**，程序无法判定。
- `character_network` 只有关系描述（青梅竹马 / 宿敌），没有**关系值/阈值**。
- 视觉小说品类本轮才补「剧情分支与结局」文档，但字段仍是文本级——**做不出分支图**。
- `story.voice_cast`（配音表）与 `audio` 的配音数量没有对齐校验。

**要补什么**：结局表（结局|条件表达式|所需关系值）；角色关系用数值 + 阈值表达。

**对应开发物**：剧情分支判定器、对话/演出数据（目前只能手写）。

## 6. 技术负责人 / 程序：「缺的是接口，不是想法」

**看到的问题**
- **数据从哪来**：本轮已解决（`data/snapshot.json` = schema + 全部行）。
- **状态怎么切**：`state_machine` 空着（同系统策划）。
- **档怎么兼容**：本轮已补 `tech.save_format`（存档项|类型|写入时机|迁移策略）。
- **缺接口/事件表**：埋点有 `analytics.event_tracking`，但**玩法事件**（开战/结算/获得物品）没有名字与参数，
  程序与策划各叫一套名，埋点就废了。
- **缺网络/服务端规格**：`tech.core_architecture` 一句 + `performance.network_adaptation` 一段文本，
  没有协议、没有权威端、没有数据一致性要求——**做联机等于从零设计**。
- **缺错误处理与边界**：断线、存档损坏、数据表缺行，文档里都没有约定。

**要补什么**：一张事件表（事件名|触发时机|参数|谁监听）；联机项目补「协议与权威端」；边界清单（断线/坏档/缺数据）。

**对应开发物**：事件总线、存档迁移代码、网络层（仅联机项目）。

## 7. 美术：「知道要什么风格，不知道要交什么文件」

**看到的问题**
- `art.*` 有风格、色彩（带色值）、字体、特效、角色/场景要点、UI 语言、动画规格、多分辨率——**质量很高**。
- 资产规格原本缺失（尺寸/格式/命名/切图-LOD/九宫格约束没有一张表）——**本轮已补**。
- `resources.art_assets` 只有「类型|数量|外包比例」，程序拿不到导入规范（已由 `art.asset_spec` 补上）。
- 敌人与 Boss 有文字描述，但**没有概念图/参考图**的位置（文档不承载图片，仍是边界）。

**要补什么**：✅ 资产规格表已补（`art.asset_spec`：类型|尺寸|格式|命名|备注，接进条件文档「资产规格与导入」）；UI 九宫格与最小可点区域属 UI 细化，建议另补。

**对应开发物**：美术需求单、导入管线规范。

## 8. 音频：「有清单，没有触发关系」

**看到的问题**
- `audio` 有配乐清单、音效清单（类别|数量|描述）、配音量、引擎（Wwise）、动态音频分层——**清单级完整**。
- 但**没有「事件 → 音效」映射**：哪个交互播哪个音、并发上限、优先级、淡入淡出时间都没写。
- **没有专属文档**：11 个角色里，音频是唯一「没有自己文档」的岗位——它只能从 `audio` 章和 `ui-feedback` 里拼。

**要补什么**：音效映射表（事件|音效 id|音量|并发上限）；给音频补一份「音频实现」文档。

**对应开发物**：音频事件表、Wwise 事件绑定。

## 9. 测试：「验收标准在，判定方式不在」

**看到的问题**
- `qa.test_case_list`（用例|类型|前置|操作|期望|状态）结构齐全，但样例里**空着**。
- `qa.acceptance_journeys`（旅程|步骤|期望）同样空着——没有旅程就没法做端到端验收。
- `prototype_acceptance`（检查项|结果|证据）是**记录表**，不是标准。
- 性能验收有 `performance.performance_budget`（表），但**没有测试方法**（怎么测、测多久、取哪一帧）。

**要补什么**：5–8 条可执行用例 + 3 条验收旅程；性能补「测量方法」一列。

**对应开发物**：验收脚本（`contract.json` 的断言 + 旅程可直接驱动）。

## 10. 运营 / 本地化：「埋点表空着，语言清单没落地」

**看到的问题**
- `analytics.event_tracking`（3 列）与 `metric_system`（4 列）在样例里空着——上线后没有数据可看。
- `live_ops` 章在模板里是空的（活动日历、版本节奏都没写）。
- `accessibility.language_list` 有 5 种语言，但**没有文案量与字体覆盖**要求，也没说 UI 是否留了 30% 余量。
- 抽卡概率与保底在 `systems.gacha` 里有配置位，但**没有对外公示口径**（合规要求）。

**要补什么**：埋点表 10 条 + 指标口径；多语言补「文案量估算 + 字体 + 余量」；抽卡概率公示。

**对应开发物**：埋点 SDK 调用点、多语言资源包、概率公示页。

## 12. 一个观察：11 个岗位里，音频没有自己的文档

这不是疏漏，而是**文档目录的偏科**：21 份文档里，系统/数值/关卡/界面各有归属，音频只能寄生在
`audio` 章（清单）与 `ui-feedback`（反馈规范）里。同理，**服务端**在非联机项目里也不需要，
但联机项目一旦需要，就没有对应文档——现在只能塞进 `tech.core_architecture`。

**已落地（2026-10-27 当日）**：加了 `HandoffDoc.when`（条件触发）与三档层级：

| 层级 | 判据 | 例子 |
|---|---|---|
| 通用基线 | 无 `genres`、无 `when` | 范围与平台、状态机、存档 |
| 品类专属 | `genres` 命中 | 敌人与 Boss、抽卡与卡池 |
| 条件文档 | `when` 命中（字段有值 / 字段取某值 / 系统启用） | 音频实现（有音频引擎或音效清单）、服务端与联机（`tech.online_mode ≠ 纯单机`） |

新增字段 `tech.online_mode`（纯单机 / 单机+排行榜 / 小规模联机 / 大规模在线）——
在此之前文档里没有任何地方说「联不联机」，条件文档只能靠猜。

同时把评审 P1 的两条「文字级」升级成**表格级**（可直接落库/落代码）：
`audio.sfx_events`（事件|音效 id|音量|并发上限）与 `tech.net_protocol`（消息|方向|频率|权威端）。
后者带「权威端」一列，客户端说了算的消息会被一眼看出来。

README 现在直接给构成统计：**通用基线 18 份（先做这些）／品类专属 +3／条件文档 +1**（RPG 样例），
并写明施工顺序：先做完通用基线，再补品类与条件——它们是**决策增量**，不是地基。
