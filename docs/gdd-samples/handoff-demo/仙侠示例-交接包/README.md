# 仙侠示例 · 开发交接包

> 生成时间：2026-10-27 03:30
> 定位：3D 仙侠开放世界 RPG，重剧情 + 轻社交 ｜ 类型：RPG ｜ 平台：PC/移动端
> 品类档案：动作 / 战斗导向
> 文档构成：**通用基线 24 份**（先做这些）；品类专属 +3 份；条件文档 +3 份
> 施工顺序：先把**通用基线**全部做完（这部分与玩法无关，任何游戏都成立）；再按标记补「品类专属」与「条件文档」——它们是**决策增量**，不是地基。

## 怎么用（给编码智能体）

1. **按编号顺序做**：从 `00-架构/01-…` 开始，一份文档做完、验收通过，再打开下一份；
2. **一次只读一份文档**：每份 100–200 行，含「要解决什么 / 要实现什么 / 规则与数据 / 验收 / 明确不做」；
3. **数据只从 `data/snapshot.json` 来**：那是唯一内容源（表结构 + 全部行），代码里不许硬编码数值；
4. **规则以 `contract.json` 为准**：规则集标识、参数表、断言、验收旅程都在里面，冲突时以它为准；
5. **`prototype/demo.html` 是参考实现**（若存在）：手感与反馈照它对齐，但不要照抄临时代码结构。

## 全局约束（每一份文档都适用）

- 数值只从参数表读，禁止魔法数字；改数值只改数据文件；
- 所有面向玩家的等待都要有可见进度；所有破坏性操作都要二次确认；
- 单局可玩性优先于内容量：先让一局好玩，再批量做关卡；
- 不实现文档「明确不做」里的东西；要加需求，先改策划书再改代码。

## 明确不做（整包范围外）

- 多人联机（MVP 暂缓）
- PVP（MVP 暂缓）
- 外观系统（MVP 暂缓）
- 成就系统（MVP 暂缓）
- 多语言（MVP 暂缓）
