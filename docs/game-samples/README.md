# 游戏真实文档样本投递槽（用于章表二次核对）

> 用途：模板语料复核（`docs/template-corpus-verification.md`）与真实文档对拍
> （`docs/template-crosscheck-real-docs.md`）都卡在同一个边界——**游戏 GDD / Art Bible / TDD
> 公开渠道没有可逐节核对的原文**。SaaS / 基础设施 / AI 文档已用 6 个公开源交叉验证过，
> 游戏章表缺这一步。本目录专门收**真实**游戏文档样本，由有文档的人提供。
>
> 对照：应用档对拍见 `docs/template-crosscheck-real-docs.md`（已完成）。

---

## 我需要什么

**1–3 份真实游戏设计文档**，任意组合以下类型：

| 类型 | 说明 | 重点核对 |
|---|---|---|
| **GDD**（游戏设计文档） | 完整或部分均可 | 章级覆盖：我们 23 章是否兜住了真实 GDD 写的全部 |
| **Art Bible**（美术圣经） | 美术风格/规范文档 | ⑧ 美术设计 章是否够用；有无美术侧专属字段缺失 |
| **TDD**（技术设计文档） | 技术/引擎/架构文档 | ⑩ 技术规格 章是否够用 |

## 形式与脱敏

- **形式**：直接把文档正文粘进本目录的 `.md` 文件即可；或贴进对话里我直接读。
  优先 Markdown / 纯文本；PDF / 图片也行，但我会多一步提取。
- **脱敏**：**可以且鼓励脱敏**——公司名、项目代号、未公开数值、截图里的敏感信息
  全部可以涂掉或替换。我要的是**章节结构、字段组织、覆盖了哪些设计维度**，不是商业机密。
- **数量**：1 份也能跑对拍；3 份能做跨样本频次统计（和 `template-corpus.md` 的中英 50 语料同口径）。

## 命名约定

```
docs/game-samples/
  gdd-<项目代号>.md        # 例：gdd-project-phoenix.md
  artbible-<项目代号>.md
  tdd-<项目代号>.md
  README.md                # 本文件
```

文件名里用代号，不要写真名。

## 收到后我做什么

1. 把样本的真实章节/字段逐条列出；
2. 与 `docs/template-crosscheck-game.md` 里的「当前游戏章基准」逐章映射；
3. 标出：✅ 已覆盖 / ⚠️ 部分覆盖 / ❌ 我们缺（并给出建议补的字段）；
4. 若发现游戏侧专属字段缺口（如美术圣经的「色彩规范 / 资产命名」、TDD 的「引擎版本 / 热更新」），
   按之前「补字段一律 optional」的原则提 PR，不抬高老文档必填门槛；
5. 输出一页结论，游戏章表即可与应用档一起**定稿**。

> 边界重申：没有真实样本，这一栏就保持「待补」，我不会拿文库/CSDN 转存当证据凑数
> （与 `template-corpus-verification.md` 一致）。
