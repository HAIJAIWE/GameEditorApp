# 窗口职责与入口矩阵（Phase B）

> **口径**：本文件回答两个问题——「每个窗口只负责什么」与「同一个能力从哪几个入口进得去」。
> 它是 `docs/ui-polish-plan.md` 的 Phase B 交付物，用来防止「两个窗口显示同一份数据却无差异说明」。
>
> **状态**：2026-11-06 初版。数字与路径以代码为准。

---

## 一、三条入口的分工（不是三套重复菜单）

| 入口 | 组织方式 | 面向的问题 | 数据来源 |
|---|---|---|---|
| **顶部菜单栏** | 按**动作语义**分 6 组（文件 / 编辑 / 工具 / 视图 / 设置 / 帮助） | 「我要做什么」 | `menusPlugin.ts` 手工声明 |
| **左侧栏** | 8 个**高频直达** | 「我常去哪」 | `navigationPlugin.tsx` 手工声明 |
| **命令面板**（Ctrl/Cmd+K） | **全量检索**，按 command / panel / mainView / conversation 分组 | 「我记得名字」 | **自动枚举** `host.commands()` / `panels()` / `mainViews()` |

> **关键差异**：菜单与侧栏是**手工编排**（会漏、会重）；命令面板是**自动枚举**（天然与注册表一致）。
> 因此「某个面板在菜单里找不到」时，命令面板一定找得到；菜单的问题优先按本文件的矩阵修。

## 二、窗口职责表

### 2.1 主区页签（`mainView`）

| 页签 | 唯一职责 | 明确不负责 |
|---|---|---|
| 策划书 | 写/改**设计文档正文**（24 章） | 不负责配数据、不负责改字段结构 |
| 数据编辑 | **录入/编辑具体条目**（角色/怪物/技能…） | 不做全局检索、不做关系分析 |
| 技术设计 | 技术向文档 | 不碰策划数值 |
| 代码编辑 | 查看/编辑库内代码文件 | 不执行代码 |
| 浏览器 | 内嵌浏览与截图 | 不代替系统浏览器 |
| 会话 | 子智能体 / 轨迹 / 定时 / 任务 / 历史的**只读看板** | 不发起对话（对话在右栏） |

### 2.2 右栏停靠

| 段 | 唯一职责 |
|---|---|
| 对话（`app.rightPanel`） | **唯一的对话入口**（发送、审批、工具卡、交付卡） |
| 会话看板 | 只读观测：子智能体状态、轨迹、定时提醒、后台任务 |

> 右栏与「会话」页签是**同一事件流的两个视图**，不是两个数据源（见 `docs/dsh-ui-comparison.md` §4.3）。

### 2.3 浮层面板（按职责分组）

| 组 | 面板 | 唯一职责 |
|---|---|---|
| 录入/编辑 | 快速创建 / 批量编辑 / 导入预览 / 字段结构 | 一次性写操作，做完即关 |
| 浏览/分析 | 高级搜索 / 关系图 / 属性图表 / 数据统计 / 数据对比 / 引用关系 / 游戏数据预览 / 属性系统 | 只读分析，不改正文 |
| 工具 | 设置 / 清理图片 / 关键词模板 / 智能体工具清单 / AI 图片生成 / MCP 配置 / 备份恢复 / 清空数据 | 配置或维护 |
| 外壳 | 关于 / 插件中心 / 插件市场 / 快速入门 / 快捷键 / 会话历史 / 执行预审 / 最近改动 | 应用级信息与管理 |

## 四、发现的问题

### P1-1 「保存 / 导出 JSON / 导出游戏数据」是同一个动作（**待决策**）

**证据**：`appActionsPlugin.ts:106` 的 `app.io.save` 实现就是 `exportJson()`；
`menusPlugin.ts` 里 `menu.file.save`、`menu.file.exportJson`、`menu.file.exportGameData` 三处都指向它。
同理 `app.io.open`（打开 / 导入 JSON）都指向 `importJson()`。

**影响**：
- 点「保存」并不会原地保存，而是弹导出对话框；
- 「导出游戏数据」与「导出 JSON」**完全没有区别**，是误导性标签。

**建议**（需产品决策，本次不改语义）：保留「保存 = 导出 JSON」作为兼容别名可以，但
「导出游戏数据」应改为**独立的游戏运行态导出**（或直接删除），否则两个标签指同一件事。

### P1-2 「平衡性分析工具」曾是假入口（**已修**）

**证据**：`menu.tools.balance` 与 `menu.tools.stats` 都指向 `statistics.open`，面板默认 `tab='overview'`
⇒ 点「平衡性分析」看到的仍是概览页。

**已修**：
- `StatisticsPanel` 新增 `initialTab`；
- 新增命令 `statistics.openBalance`，以 `{ tab: 'balance' }` 打开；
- `menu.tools.balance` 改指新命令；
- 回归测试 `statisticsPlugin.test.tsx` 断言「balance 页签 active + 显示平衡性空态」。

### P2-1 「模板管理」与「字段结构编辑器」是同一面板（**待决策**）

**证据**：`menu.edit.templateManager` 与 `menu.tools.fieldEditor` 都指向 `typeEditor.open`，
面板标题是「字段结构编辑器」。

**建议**：统一命名（保留「字段结构」），把「模板管理」改成同一文案或直接删掉一个入口。
删入口会动 e2e 的 `menuitem-edit-templateManager` 锚点，需同批改测试。

### P2-2 「批量编辑」出现在「文件 → 导出」下（**待决策**）

**证据**：`menu.file.batchEdit` 与 `menu.tools.batchEdit` 都指向 `batch.open`。

**建议**：批量编辑不是导出动作，File → 导出 下的那一项应删除；保留「工具 → 批量编辑」。
删除需同步 e2e 的 `menuitem-file-batchEdit` 锚点。

### P3 侧栏与菜单重叠（**可接受**）

关系图 / 高级搜索 / 统计 / 设置 / 关于 同时在侧栏与菜单。这是**快捷方式**而非重复实现，保留。
唯一可优化的是「关于」（低频）只留 Help；但它也是侧栏末尾的固定位置，删除收益低，暂不动。

## 五、维护约定

1. **新增能力**：至少给一个菜单或侧栏入口；命令面板会自动收录，不需要额外登记。
2. **同一命令多标签**：允许（历史上「保存/导出 JSON」就是），但**必须在菜单注释里写明**
   「同实现多标签」，否则下一个人会当成 bug 修。
3. **删除入口**：同步改 `tests/e2e/*.spec.ts` 里的 `menuitem-*` 锚点；`data-testid` 是契约。
4. **面板参数**：需要「同一面板不同初始态」时，用 `openPanel(id, { tab })` 这类**显式参数**，
   不要靠「先打开再点一下」——那会变成假入口（P1-2 就是教训）。
