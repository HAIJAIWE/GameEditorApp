# 面向 LLM 与真人的游戏策划案通用写作指南

> 📌 **这是什么**：给 AI 用的游戏策划书写作规范，AI 生成策划书时会参考这个文档来保证输出质量。
> **什么时候用**：一般不动它，除非要调整 AI 生成策划书的风格或结构。`

> 版本定位：基础通用版  
> 使用对象：真人策划、产品负责人、制作人、LLM 生成系统、项目协作成员  
> 核心原则：不锁死玩法方向；底层系统模块化；数值系统先建骨架，再根据玩法方向填充参数。

---

# 第一部分：文档定位与使用说明

## 1.1 文档目标

本文档用于指导真人策划与 LLM 撰写游戏策划案。它不是某一款具体游戏的最终策划案，而是一套可复用的通用写作规范、系统设计框架、数值设计骨架与玩法方向示例。

本文档适用于以下场景：

1. 项目早期，玩法方向尚未完全确定。
2. 需要先搭建游戏策划案基础结构。
3. 需要让 LLM 理解游戏策划案应该如何写。
4. 需要让真人策划、程序、美术、运营能够阅读和补充。
5. 需要后续根据不同玩法方向动态调整。

## 1.2 基础通用版原则

基础通用版不是低质量简版，而是早期项目最重要的底层框架。它的重点不是把所有细节一次写满，而是建立一套稳定、清晰、可扩展的设计结构。

基础通用版应遵循以下原则：

1. 不在早期锁死具体玩法方向。
2. 不填入大量未经验证的最终数值。
3. 先定义核心体验、核心循环和系统关系。
4. 底层系统采用模块化设计。
5. 数值系统先建立公式、变量、边界和调优方式。
6. 所有章节保留后续动态调整空间。
7. 文档同时服务于真人阅读和 LLM 生成。

## 1.3 不锁死玩法方向原则

如果项目尚未确认最终玩法，不应直接写成“本游戏是一款卡牌 RPG”“本游戏是一款 ARPG”“本游戏是一款经营模拟游戏”。

推荐写法：

> 本项目当前处于基础通用版策划阶段，暂不锁死具体玩法方向。后续可根据核心体验验证结果，将项目扩展为战斗驱动、养成驱动、策略驱动、休闲驱动、经营模拟或混合玩法方向。

## 1.4 模块化设计原则

模块化设计是为了让游戏底层系统可以被复用、替换和扩展。

常见底层模块包括：

- 玩家系统
- 角色系统
- 成长系统
- 战斗/挑战系统
- 资源系统
- 道具系统
- 奖励系统
- 任务系统
- 关卡/地图系统
- 商店系统
- 活动系统
- 社交系统，可选
- 排行榜系统，可选
- 数据配置系统

## 1.5 数值先建骨架原则

数值系统在早期不应以“拍参数”为主，而应先确定：

1. 有哪些属性。
2. 属性之间如何发生关系。
3. 成长曲线如何构建。
4. 战斗或挑战如何结算。
5. 资源如何产出、消耗和回收。
6. 掉落概率如何控制。
7. 哪些参数后续可以动态调整。
8. 如何验证数值是否合理。

# 第三部分：各章节写作规范

## 3.1 项目概述

### 章节目的

用简洁语言说明项目是什么、面向谁、当前处于什么阶段。

### 应包含内容

- 游戏名称
- 游戏类型，暂定即可
- 平台
- 目标用户
- 核心体验
- 一句话玩法描述
- 当前版本定位
- 后续玩法方向说明

### 不应包含内容

- 不应过早锁死最终玩法类型。
- 不应写入未经验证的最终商业化方案。
- 不应大量填写最终数值参数。

### 推荐模板

| 项目 | 内容 |
|---|---|
| 游戏名称 | 暂定：XXX |
| 当前版本 | 基础通用版 |
| 游戏类型 | 暂不锁死，可向多方向扩展 |
| 目标平台 | 移动端 / PC / Web / 小程序 / 多端 |
| 目标用户 | 待定，初步面向轻中度或中度用户 |
| 核心体验 | 成长、挑战、反馈、策略、收集或经营等 |
| 玩法方向 | 后续根据验证结果动态调整 |

## 3.2 核心设计理念

### 章节目的

说明游戏最重要的设计原则和体验目标。

### 推荐写法

> 本项目以可扩展的核心循环为基础，通过清晰的目标、持续的反馈和可感知的成长，构建适用于多玩法方向的底层体验。当前阶段优先验证玩家是否愿意重复进行核心行为，并通过奖励、成长和解锁形成长期驱动力。

### 常见设计原则

1. 先验证核心循环，再扩展复杂系统。
2. 前期反馈要明确，中后期目标要持续。
3. 系统之间要有输入输出关系。
4. 数值应服务体验，而不是单纯堆复杂度。
5. 后续方向变化时，尽量调整模块权重，而不是推倒重来。

## 3.3 目标用户与体验目标

### 目标用户字段

| 字段 | 说明 |
|---|---|
| 年龄层 | 可暂定 |
| 游戏经验 | 轻度 / 中度 / 重度 |
| 偏好 | 战斗、收集、养成、经营、策略、休闲等 |
| 单次时长 | 短局 / 中局 / 长线 |
| 付费倾向 | 免费、广告、轻付费、中重度付费等 |

### 体验目标示例

| 体验目标 | 说明 |
|---|---|
| 成长感 | 玩家每次游玩后都能获得提升 |
| 目标感 | 玩家知道下一步要追求什么 |
| 策略感 | 不同选择带来不同结果 |
| 反馈感 | 操作、奖励、升级、解锁都有反馈 |
| 可扩展性 | 后续能接入不同玩法方向 |

## 3.4 核心玩法与核心循环

### 基础核心循环

```text
进入游戏
→ 选择目标/关卡/任务
→ 进行核心玩法
→ 获得奖励
→ 消耗奖励进行成长
→ 解锁新内容/更高难度
→ 再次进入核心玩法
```

### 通用循环模板

```text
完成一次核心行为
→ 获得资源或进度
→ 使用资源提升能力
→ 解锁更高价值目标
→ 形成重复游玩动机
```

### 可适配方向

| 玩法方向 | 核心循环表现 |
|---|---|
| 战斗驱动 | 战斗 → 掉落 → 强化 → 挑战更强敌人 |
| 养成驱动 | 获取资源 → 培养角色 → 解锁内容 → 继续养成 |
| 策略驱动 | 配置阵容 → 进行对局 → 复盘调整 → 挑战更复杂关卡 |
| 休闲驱动 | 完成关卡 → 获得奖励 → 解锁新关卡/道具 |
| 经营驱动 | 生产资源 → 完成订单 → 扩建升级 → 提高产能 |

## 3.5 市场分析

### 章节目的

分析目标市场规模、竞品情况和差异化定位，为项目立项提供数据支撑。

### 应包含内容

- 目标市场规模（引用第三方数据，标注来源和年份）
- 竞品分析（至少 3 款，覆盖成功和失败案例）
- 差异化定位（明确"我们比竞品好在哪"）
- 市场趋势（基于数据，不凭感觉）
- 市场定位（一句话说清"我们是谁、给谁、比竞品好在哪"）

### 写作要点

1. 竞品分析要具体到优势、劣势、创新度评分、完成度评分，并标注"借鉴/规避"。
2. 差异化定位必须明确说出"我们比竞品好在哪"，而非泛泛的"我们有创新"。
3. 市场趋势要基于第三方数据（Newzoo/Sensor Tower/伽马数据），标注数据来源和年份。
4. 竞品类型分为直接竞品、间接竞品、潜在竞品，分类要准确。

## 3.6 世界观与表现风格

### 章节目的

定义世界观设定、视觉风格和情绪目标，确保世界观支撑核心玩法。

### 应包含内容

- 世界观设定（具体的、不可调和的核心冲突）
- 视觉风格（参考作品、色调倾向、美术风格）
- 情绪目标（2-3 个核心情绪词及实现方式）

### 写作要点

1. 世界观不是"有邪恶势力"，是具体的、不可调和的矛盾。
2. 视觉风格应与世界观和核心体验一致，列出参考作品。
3. 情绪目标指导所有设计决策——从色彩到音效到 UI 节奏。

## 3.7 底层系统模块设计

### 章节目的

从核心循环推导需要的底层系统，每个系统有明确的输入输出和关联关系。

### 应包含内容

系统模块清单，每个系统使用统一结构：系统名称、系统定位、系统目标、核心功能、输入、输出、关联模块、可配置参数、后续扩展方向。

### 写作要点

1. 使用统一结构描述每个系统，便于程序和策划对齐。
2. 系统之间要形成完整的输入输出网络，不能有孤立系统。
3. 不锁死具体实现，保留扩展空间。详见第四部分。

## 3.8 角色与成长系统

### 章节目的

定义角色字段和成长类型，制造玩家长期目标和持续变强的体验。

### 应包含内容

- 角色推荐字段（角色ID、名称、定位、稀有度、基础属性、成长属性、技能）
- 成长类型（等级/装备/技能/资源/内容/收藏）
- 成长设计原则

### 写作要点

1. 角色字段使用游戏世界观术语命名，字段定义完整。
2. 成长类型覆盖全面，基础版本应控制成长线数量。
3. 成长原则可量化验证，能指导具体数值设计。

## 3.9 战斗/挑战系统

### 章节目的

定义战斗/挑战的完整流程，承载玩家主要主动行为。

### 应包含内容

- 基础流程（进入挑战 → 读取状态 → 生成敌人/关卡 → 操作/结算 → 计算结果 → 发放奖励 → 更新进度）
- 输入（玩家属性、角色状态、技能配置、关卡配置、敌人配置、道具效果）
- 输出（胜负结果、奖励、经验、资源、掉落、关卡进度）

### 写作要点

1. 流程闭环无遗漏，每个步骤标注输入和输出。
2. 非战斗游戏可理解为"挑战系统"，逻辑结构一致。
3. 输出能驱动后续系统（成长、奖励等）。

## 3.10 AI 行为设计

### 章节目的

定义游戏中 AI 的行为模式、难度分级和性能预算，确保 AI 行为可读、可调、可控。

### 应包含内容

- 敌人 AI 状态机（状态定义、转移条件、行为输出）
- 难度分级（简单/普通/困难/噩梦，各级参数差异）
- 性能预算（同屏 AI 数量上限、决策频率、LOD 策略）

### 写作要点

1. **敌人 AI 状态机写法**：使用"状态—转移条件—行为"三段式描述每个状态。状态名使用枚举（如 `IDLE/PATROL/CHASE/ATTACK/FLEE/DEAD`），转移条件必须是可量化的事件（如"距离玩家<5 米 → CHASE"），行为输出标注参数（如"攻击：伤害=ATK×1.5，冷却=2s"）。
2. **难度分级写法**：每个难度级别标注关键参数差异（敌人血量、攻击力、AI 反应时间、决策频率），使用倍率表而非绝对值。如"困难模式：敌人血量×1.5，ATK×1.3，反应时间-30%"。
3. **性能预算写法**：明确同屏 AI 数量上限、每帧决策预算（如"≤2ms"）、LOD 策略（远距离 AI 降频或冻结）。性能预算必须可测试、可监控。

## 3.11 资源与经济系统

### 章节目的

管理资源的产出、消耗、存储与回收，维护经济循环健康。

### 应包含内容

- 资源分类（基础货币、高级货币、成长材料、消耗道具、稀有材料、付费资源）
- 资源流转（产出来源和消耗去向）

### 写作要点

1. 经济循环必须闭环，有回收防通胀。
2. 每类资源标注作用和典型示例。
3. 产出端和消耗端分别列出，确保每个资源都有明确路径。

## 3.12 道具与奖励系统

### 章节目的

将玩家行为转化为正反馈，奖励必须与核心循环绑定。

### 应包含内容

- 奖励类型（固定/随机掉落/阶段/首通/排名/活跃/保底）
- 设计重点

### 写作要点

1. 奖励不能只作为填充内容存在，必须与核心循环绑定。
2. 奖励的稀缺性和获取难度应与奖励价值匹配。
3. 每次核心行为完成后，玩家应获得明确的、有意义的奖励反馈。

## 3.13 任务与关卡系统

### 章节目的

任务系统引导玩家理解玩法、提供短期目标；关卡系统控制难度节奏、承载玩法变化。

### 应包含内容

- 任务系统目标（引导玩法、短期目标、推动解锁、绑定奖励节奏）
- 关卡系统目标（控制难度、承载变化、承载产出、版本推进载体）

### 写作要点

1. 任务目标能覆盖玩家从新手到老手的完整旅程。
2. 关卡目标能支撑长期内容规划。
3. 每条目标对应具体的设计手段。

## 3.14 教程设计

### 章节目的

定义新手教学流程，让玩家在 5 分钟内理解核心玩法，在不破坏沉浸感的前提下完成教学。

### 应包含内容

- 教学流程（教学步骤序列、每步目标、时长预算）
- 触发条件（基于行为/时间/进度/失败次数的触发规则）
- 失败容错（玩家卡住时的兜底策略、跳过选项、重复触发）

### 写作要点

1. **教学流程写法**：按"操作示范→引导尝试→独立完成→强化反馈"四段式描述每个教学步骤。每步标注教学目标、输入操作、预期反馈、时长预算（如"步骤 1：移动教学，目标=学会移动，操作=摇杆/方向键，反馈=角色移动+粒子特效，时长=15s"）。
2. **触发条件写法**：触发条件必须可量化，使用"事件+条件→动作"格式。如"玩家进入主城 AND 未完成移动教学 → 触发移动教学"。避免"适当时候"等模糊表述。
3. **失败容错写法**：定义失败判定（如"30s 未完成操作"）和兜底策略（跳过、降低难度、NPC 示范、自动完成）。提供"跳过教学"选项，但跳过后补发教学奖励。

## 3.15 数值系统基础框架

### 章节目的

建立数值骨架，服务玩家体验，不堆复杂度。

### 应包含内容

基础属性、属性分层、等级经验公式、属性成长公式、伤害公式、技能伤害公式、战力公式、资源产消公式、掉落概率公式、验证方法、动态调优规则。

### 写作要点

1. 公式完整、变量定义清晰，先写基础版再写进阶版。
2. 验证方法覆盖升级速度、战斗时长、通关率、资源盈余、掉落体验、付费影响。
3. 所有关键参数必须配置化，调参记录版本和影响范围。详见第五部分。

## 3.16 玩法方向动态扩展

### 章节目的

在基础框架下展示如何向不同玩法方向扩展，不锁死方向。

### 应包含内容

5 个方向（战斗/养成/策略/休闲/经营）的核心体验、强化模块、弱化模块、数值重点、风险。

### 写作要点

1. 方向之间有差异化，分析有深度。
2. 每个方向标注强化哪些模块、弱化哪些模块。
3. 不锁死方向，只展示扩展可能性。详见第六部分。

## 3.17 UI 与交互设计

### 章节目的

定义 UI 风格、HUD 布局、菜单结构和界面流程。

### 应包含内容

- UI 风格（整体语言、信息层级原则、参考游戏）
- HUD 布局（每个元素的位置和优先级）
- 菜单结构（缩进树形结构，无死路）
- 界面流程（所有界面的流转关系，每个页面有入口出口）

### 写作要点

1. UI 支持核心玩法，布局符合直觉。
2. HUD 每个元素都要问"玩家真的需要一直看到吗"。
3. 流程清晰无死路，每个页面有明确的入口和出口。

## 3.18 商业化与运营预留

### 章节目的

定义付费模式、首充设计、付费路径和付费用户分层，从玩家第一次付费到持续消费的完整路径。

### 应包含内容

付费模式、首充设计、付费路径、不卖什么、付费用户分层（大R/中R/小R/免费）、LTV/CAC 目标、付费渗透率、月卡/通行证/抽卡设计、反作弊策略、合规要求、商业化 KPI。

### 写作要点

1. **LTV/CAC 测算**：LTV = ARPU × 生命周期天数；LTV/CAC 应 ≥ 3 才健康。必须同时给出 LTV 目标和 CAC 目标。
2. **付费分层写法**：大R/中R/小R/免费用户分别标注占比目标和 ARPU 目标，占比合计 100%。
3. 付费是阶梯不是深渊，每级都要让玩家觉得比上一级值。
4. 明确"不卖什么"比"卖什么"更重要——玩家最怕未知的付费墙。
5. 合规要求覆盖国内（版号+未成年人保护+概率公示）和海外（GDPR+COPPA+Apple/Google 政策）。

## 3.19 MVP 原型版本规划

### 章节目的

用最少的内容验证最核心的假设——不是简化版，是验证版。

### 应包含内容

MVP 范围、系统清单、核心验证假设、成功 KPI、开发工时估算、验证方法、失败标准、资源需求。

### 写作要点

1. **核心假设写法**：通常是一个"玩家是否愿意..."的问题。如"玩家是否愿意为轻量化开放世界重复战斗 10 次以上"。
2. **KPI 设定要点**：必须量化，如次日留存 30%、平均时长 8 分钟、重复游玩率 40%。
3. **失败标准**：必须明确什么情况下验证失败，如"次日留存<20% 或 重复游玩率<20% 则验证失败"。
4. MVP 范围能在一周内完成原型验证，只列验证核心循环必需的项。

## 3.20 数据验证与动态调优

### 章节目的

上线前定好追踪和验证什么，数据驱动调优。

### 应包含内容

验证项（升级速度/战斗时长/通关率/资源盈余/掉落体验/付费影响）、调优规则。

### 写作要点

1. **埋点方案写法**：覆盖核心行为路径（登录、进入关卡、完成关卡、获得奖励、付费、流失），每个埋点标注事件名、触发时机、携带参数。
2. **上线 checklist**：数据看板搭建完成、埋点验证通过、报警阈值设定、A/B 测试框架就绪。
3. 每个验证项标注可量化目标和验证方法。
4. 调优规则要具体可执行：区分体验问题、数值问题和内容问题。

## 3.21 风险、待确认问题与后续迭代

### 章节目的

提前识别风险，把惊喜变成预期。

### 应包含内容

风险清单、待确认问题、后续迭代方向。

### 写作要点

1. **8 大风险维度**：技术风险、设计风险、市场风险、团队风险、时间风险、法律风险、资金风险、运营风险。每个风险必须归类到这 8 类之一。
2. **枚举约束写法**：每个风险写清类别（8 选 1）、概率（高/中/低）、影响（高/中/低）、负责人、缓解方案、应急预案、状态（已缓解/监控中/已发生/已关闭）、触发条件。
3. 概率和影响使用枚举值，不用自由文本，便于筛选和排序。
4. 待确认问题标注决策时机和依赖条件。

## 3.22 美术方案

### 章节目的

定义美术方向、色彩方案和角色/场景设计。

### 应包含内容

- 美术方向（整体风格+参考作品+选择理由）
- 色彩方案（主色调/辅助色/功能色/情绪色）
- 角色设计（比例、风格、辨识度）
- 场景设计（风格、色调、主题区域）

### 写作要点

1. 美术风格与玩法匹配，拿参考图贴旁边。
2. 色彩系统统一：主色调决定第一印象，功能色用于 UI，情绪色根据场景变化。
3. 角色剪影可辨识，能区分不同角色类型。

## 3.23 音频设计

### 章节目的

定义音频方向、BGM 情绪表和核心音效。

### 应包含内容

- 音频方向（整体风格、参考作品）
- BGM 情绪表（场景、情绪、节奏、参考曲）
- 核心音效（最重要的 10 个音效及重要性说明）

### 写作要点

1. 写情绪和触发逻辑，不是具体曲目名。
2. 每个场景一种情绪，BGM 是引导玩家情绪的工具。
3. 核心音效覆盖攻击命中、技能释放、升级提示、获得稀有物品等关键反馈。

## 3.24 技术方案

### 章节目的

从核心玩法推导技术需求，选型有据可依。

### 应包含内容

- 引擎/框架（Unity/Unreal/Godot/Cocos2d/自研/待定）
- 核心技术风险（技术难点和备选方案）
- 性能目标（帧率/内存/包体/加载时间，分平台列）
- 里程碑（原型/Alpha/Beta/上线，每个阶段交付物和时间节点）

### 写作要点

1. 选型理由充分：根据目标平台、团队经验和项目需求选择引擎。
2. 核心技术风险要诚实标红，有备选方案。
3. 性能目标可量化、可测试，分平台定义。
4. 每个里程碑有可验证的交付标准。

## 3.25 配置表设计

### 章节目的

策划和程序的契约，实现数据驱动的游戏设计。

### 应包含内容

推荐配置表清单（表名、用途）。

### 写作要点

1. **表结构规范**：表名使用小写+下划线命名（如 `character_config`、`stage_config`）；每张表第一列为 ID 主键；每张表标注用途。
2. **外键关系**：明确表与表之间的引用关系，如 `stage_config.enemy_id` 引用 `enemy_config.id`、`drop_config.reward_id` 引用 `reward_config.id`。
3. 配置表覆盖所有需要策划配置的数据：全局参数、角色、等级、技能、关卡、敌人、资源、掉落、奖励、商店、任务。
4. 命名规范统一，便于程序自动加载和热更新。

## 3.26 无障碍设计

### 章节目的

确保游戏对不同能力的玩家都可访问，覆盖视觉、听觉、运动障碍人群，提升受众覆盖面和合规性。

### 应包含内容

- 色盲支持（色觉适配方案、形状/图标辅助、色彩可调）
- 字幕支持（对话字幕、音效字幕、字幕样式可调）
- 运动辅助（按键重映射、操作辅助、难度可调、暂停模式）

### 写作要点

1. **色盲支持写法**：列出支持的色觉类型（红绿色盲、蓝黄色盲、全色盲），标注哪些游戏元素依赖颜色区分（如"血条红/蓝 → 增加形状标识三角形/圆形"）。提供色彩可调方案（预设方案+自定义）。
2. **字幕支持写法**：所有语音对话必须有字幕，标注字幕触发时机、显示时长（按字数计算，如"每字 0.3s"）、样式可调（字号、颜色、背景）。音效字幕标注音效类型（如"[爆炸声]"、"[脚步声]"）。
3. **运动辅助写法**：支持按键重映射（每个操作可绑定任意按键）、操作辅助（自动瞄准、QTE 自动完成、慢速模式）、随时暂停（回合制/暂停菜单）。标注每项辅助的影响范围（是否影响成就/排行）。

## 3.27 项目管理

### 章节目的

定义项目里程碑、团队配置和预算估算，确保项目可执行、可追踪、可交付。

### 应包含内容

- 里程碑（原型/Alpha/Beta/上线/运营，每个阶段交付物和时间节点）
- 团队配置（岗位、人数、职责、到岗时间）
- 预算估算（人力成本、工具/服务成本、营销成本、缓冲预算）

### 写作要点

1. **里程碑写法**：每个里程碑标注名称、时间节点、交付物清单（可验证）、验收标准、依赖项。如"Alpha（2026-09-01）：核心玩法可玩，交付物=1 关卡+1 角色+战斗系统，验收标准=核心循环跑通，依赖=战斗系统开发完成"。
2. **团队配置写法**：按岗位列出人数、职责、到岗时间、关键技能要求。标注关键岗位的 AB 角配置（如"主程 A：张三，B：李四"）。团队规模与里程碑匹配，避免过度扩张。
3. **预算估算写法**：按类别列出预算（人力、工具/服务、营销、缓冲），人力成本按"人数×月薪×月数"计算。预留 15-20% 缓冲预算应对风险。预算与里程碑挂钩，分阶段释放。

## 3.28 营销计划

### 章节目的

定义营销渠道、KPI 和预算分配，确保产品触达目标用户并实现获客目标。

### 应包含内容

- 渠道策略（自有渠道、付费渠道、社媒渠道、KOL/达人渠道）
- KPI 设定（曝光量、点击率、转化率、CAC、ROI）
- 预算分配（各渠道预算占比、分阶段投放计划）

### 写作要点

1. **渠道策略写法**：每个渠道标注目标用户匹配度、获客成本预估、内容形式要求。区分自有渠道（官网/社群/公众号）、付费渠道（买量/信息流）、社媒渠道（B站/抖音/Twitter）、KOL 渠道（达人合作）。如"抖音信息流：目标用户匹配度=高，CAC 预估=15 元，内容形式=15s 竖版视频"。
2. **KPI 设定写法**：KPI 必须量化且分层——曝光层（曝光量、CPM）、点击层（点击率、CPC）、转化层（转化率、CAC）、留存层（次日留存、七日留存）、变现层（LTV、ROI）。每个 KPI 标注目标值和行业基准。
3. **预算分配写法**：按渠道列出预算占比和金额，标注投放节奏（预热期/上线期/稳定期）。如"总营销预算 50 万：买量 60%（30 万）、KOL 20%（10 万）、社媒内容 10%（5 万）、缓冲 10%（5 万）"。预算分配与 KPI 挂钩，定期复盘调整。

## 3.29 运营计划

### 章节目的

定义赛季规划、活动规划和内容路线图，确保游戏上线后有持续的内容更新和活跃运营。

### 应包含内容

- 赛季规划（赛季周期、赛季主题、赛季奖励、赛季内容量）
- 活动规划（活动类型、活动节奏、活动奖励、活动目标）
- 内容路线图（6-12 个月内容更新计划，标注版本节点）

### 写作要点

1. **赛季规划写法**：每个赛季标注周期（如"4 周/赛季"）、主题、新增内容（角色/关卡/玩法）、赛季奖励结构（免费/付费通行证）、赛季 KPI（DAU 提升、付费提升）。如"S1（上线后第 1-4 周）：主题=暗影降临，新增=2 角色+10 关卡，奖励=限定皮肤+通行证"。
2. **活动规划写法**：活动类型分类（节日活动/联动活动/限时挑战/福利活动），每个活动标注时间窗口、目标（拉新/促活/回流/变现）、奖励池、开发工时。活动节奏避免冲突，保持每周至少 1 个活跃活动。
3. **内容路线图写法**：按月/季度列出内容更新计划，标注版本号、内容主题、新增系统、预期 KPI 影响。路线图保留弹性，根据数据反馈调整优先级。如"M+1：v1.1 新增公会系统，预期 DAU+10%；M+3：v1.2 新增 PVP 玩法，预期留存+5%"。

# 第四部分：底层系统模块化设计规范

每个系统建议使用统一结构：

```text
系统名称：
系统定位：
系统目标：
核心功能：
输入：
输出：
关联模块：
可配置参数：
后续扩展方向：
```

## 4.1 玩家系统

### 系统定位

玩家系统用于记录玩家账号、等级、进度、资源、解锁状态与行为数据。

### 核心功能

1. 玩家基础信息管理。
2. 玩家等级与经验记录。
3. 玩家资源与资产记录。
4. 玩家关卡/任务进度记录。
5. 玩家系统解锁状态记录。

### 输入

登录、游玩行为、任务完成、奖励发放、资源变动。

### 输出

玩家等级、进度、资源余额、解锁状态、数据统计。

### 可配置参数

等级上限、经验需求、功能解锁条件、每日限制、资源上限。

## 4.2 角色系统

### 系统定位

角色系统用于承载玩家可操作、可培养、可收集或可派遣的对象。

### 核心功能

1. 角色基础属性。
2. 角色定位。
3. 角色技能。
4. 角色成长。
5. 角色稀有度，可选。
6. 角色收集与解锁。

### 推荐字段

| 字段 | 说明 |
|---|---|
| 角色ID | 唯一编号 |
| 角色名称 | 展示名称 |
| 定位 | 输出、防御、辅助、控制、生产等 |
| 稀有度 | 普通、稀有、史诗、传说等 |
| 基础属性 | 生命、攻击、防御、速度等 |
| 成长属性 | 每级成长或成长倍率 |
| 技能 | 主动、被动或特殊能力 |

## 4.3 成长系统

### 系统定位

成长系统用于制造玩家长期目标和持续变强的体验。

### 成长类型

| 类型 | 示例 |
|---|---|
| 等级成长 | 玩家等级、角色等级、建筑等级 |
| 装备成长 | 强化、升星、洗练、镶嵌 |
| 技能成长 | 技能升级、技能树、天赋 |
| 资源成长 | 产出效率提升、容量提升 |
| 内容成长 | 新地图、新关卡、新玩法 |
| 收藏成长 | 图鉴、卡牌、宠物、皮肤 |

### 设计原则

1. 前期成长快，建立反馈。
2. 中期增加选择，形成策略。
3. 后期设置长期目标，避免内容枯竭。
4. 不同成长线之间需要权重控制。
5. 避免某一成长线收益过高导致系统失衡。

## 4.4 战斗/挑战系统

### 系统定位

战斗/挑战系统用于承载玩家的主要主动行为。若项目不是战斗游戏，也可将其理解为“挑战系统”。

### 基础流程

```text
进入挑战
→ 读取玩家状态
→ 生成敌人/关卡/事件
→ 玩家操作或系统结算
→ 计算结果
→ 发放奖励
→ 更新进度
```

### 输入

玩家属性、角色状态、技能配置、关卡配置、敌人配置、道具效果。

### 输出

胜负结果、奖励、经验、资源、掉落、关卡进度。

## 4.5 资源系统

### 系统定位

资源系统负责管理游戏内所有资源的产出、消耗、存储与回收。

### 资源分类

| 类型 | 作用 | 示例 |
|---|---|---|
| 基础货币 | 高频消耗 | 金币、木材、粮食 |
| 高级货币 | 稀缺资源 | 钻石、宝石 |
| 成长材料 | 用于养成 | 强化石、经验书 |
| 消耗道具 | 一次性使用 | 药水、门票、加速券 |
| 稀有材料 | 长线追求 | 碎片、核心、图纸 |
| 付费资源 | 商业化相关 | 充值货币、礼包券 |

### 资源流转

```text
产出来源：任务 / 关卡 / 掉落 / 挂机 / 活动 / 付费 / 社交
消耗去向：升级 / 强化 / 合成 / 抽取 / 商店 / 交易 / 活动
```

## 4.6 奖励系统

### 系统定位

奖励系统用于将玩家行为转化为正反馈。

### 奖励类型

1. 固定奖励。
2. 随机掉落。
3. 阶段奖励。
4. 首通奖励。
5. 排名奖励。
6. 活跃奖励。
7. 保底奖励。

### 设计重点

奖励必须与核心循环绑定，不能只作为填充内容存在。

## 4.7 任务与关卡系统

### 任务系统目标

1. 引导玩家理解玩法。
2. 提供短期目标。
3. 推动系统解锁。
4. 绑定奖励和成长节奏。

### 关卡系统目标

1. 控制难度节奏。
2. 承载玩法变化。
3. 承载资源产出。
4. 作为版本内容推进载体。

# 第五部分：数值系统基础框架写作规范

## 5.1 数值设计目标

数值系统的目标不是让数字复杂，而是服务玩家体验。

核心目标包括：

1. 控制游戏节奏。
2. 制造成长感。
3. 保持挑战性。
4. 支撑策略选择。
5. 维护经济循环。
6. 支持版本调优。

## 5.2 基础属性定义

| 属性 | 说明 |
|---|---|
| HP / 生命值 | 决定承受伤害能力 |
| ATK / 攻击力 | 决定基础输出能力 |
| DEF / 防御力 | 决定减伤能力 |
| SPD / 速度 | 决定行动顺序或行动频率 |
| CRIT / 暴击率 | 决定爆发概率 |
| CRIT_DMG / 暴击伤害 | 决定暴击收益 |
| HIT / 命中 | 抵消闪避 |
| DODGE / 闪避 | 规避伤害 |
| RES / 抗性 | 抵抗控制或元素伤害 |

## 5.3 属性分层

| 层级 | 属性 | 作用 |
|---|---|---|
| 一级属性 | 生命、攻击、防御 | 决定基础能力 |
| 二级属性 | 暴击、闪避、命中、速度 | 决定随机性和策略性 |
| 三级属性 | 穿透、减免、抗暴、增伤 | 决定后期深度和差异 |

## 5.4 成长曲线

### 等级经验公式

```text
升级所需经验 = 基础经验 × 当前等级 ^ 成长系数
```

### 变量说明

| 变量 | 说明 |
|---|---|
| 基础经验 | 控制前期升级速度 |
| 当前等级 | 玩家或角色当前等级 |
| 成长系数 | 控制中后期成长速度 |

### 角色属性成长

```text
当前属性 = 初始属性 + 成长值 × 当前等级
```

进阶版：

```text
当前属性 = 初始属性 × 等级成长倍率 × 装备倍率 × 技能倍率 × 其他加成
```

## 5.5 战斗/挑战公式

### 简单攻防公式

```text
最终伤害 = max(攻击力 - 防御力, 最小伤害)
```

适用于轻度玩法、早期原型和简单自动战斗。

### 百分比减伤公式

```text
减伤率 = 防御力 / (防御力 + 常数K)
最终伤害 = 攻击力 × (1 - 减伤率)
```

适用于长线成长、RPG、PVE/PVP 兼容玩法。

### 技能伤害公式

```text
技能伤害 = 攻击力 × 技能倍率 + 技能基础伤害
```

进阶版：

```text
最终伤害 = (攻击力 × 技能倍率 + 技能基础伤害)
× 暴击修正
× 增伤修正
× 防御修正
× 随机浮动
```

## 5.6 战力计算框架

```text
战力 = 生命值 × 生命权重
     + 攻击力 × 攻击权重
     + 防御力 × 防御权重
     + 暴击率 × 暴击权重
     + 速度 × 速度权重
```

注意：战力只适合作为参考指标，不应完全代表真实强度。

## 5.7 资源产出与消耗

### 资源产出公式

```text
单次产出 = 基础产出 × 难度系数 × 关卡系数 × 掉落倍率
```

### 资源消耗公式

```text
升级消耗 = 基础消耗 × 等级 ^ 消耗成长系数
```

## 5.8 掉落概率框架

### 基础概率

```text
掉落结果 = 随机数 <= 掉落概率
```

### 保底概率

```text
实际概率 = 基础概率 + 未掉落次数 × 概率补偿
```

## 5.9 数值验证方法

| 验证项 | 目标 |
|---|---|
| 升级速度 | 前期快，中期稳定，后期可持续 |
| 战斗时长 | 控制在目标区间 |
| 通关率 | 难度曲线合理 |
| 资源盈余 | 不长期爆仓，不长期短缺 |
| 掉落体验 | 稀有物有追求但不绝望 |
| 付费影响 | 不破坏核心体验 |

## 5.10 动态调优规则

1. 所有关键参数必须配置化。
2. 每次调参记录版本、原因和影响范围。
3. 优先调整参数，不轻易修改系统结构。
4. 先小范围测试，再扩大应用。
5. 区分体验问题、数值问题和内容问题。

# 第七部分：LLM 生成规则

## 7.1 默认规则

当用户没有明确指定玩法方向时，LLM 应默认采用“基础通用版”写法。

1. 禁止过早锁死玩法方向。

3. 禁止只列标题不解释用途。
4. 禁止只写世界观不写系统。
5. 禁止只写数值公式不说明变量。
6. 禁止忽略后续动态调整。

## 7.3 推荐输出结构

```text
章节名称
章节目的
设计说明
具体内容
可配置项
后续扩展
风险点
```

- “暂定”
- “后续根据测试结果确定”
- “可向多个方向扩展”
- “当前阶段仅建立基础框架”
- “具体参数待玩法方向确认后填充”

## 7.5 LLM 写作提示词模板

4. 每个系统说明定位、输入、输出、关联模块和可配置参数。

# 第九部分：完整玩法策划方案示例

以下示例用于展示在基础通用框架下，如何扩展成不同玩法方向的游戏策划方案。示例不是最终项目方案，而是可供 LLM 和真人参考的写作范本。

## 示例一：战斗驱动方向游戏策划方案

### 1. 项目概述

本示例为战斗驱动方向的基础游戏策划方案，适用于动作、轻 ARPG、Roguelite 战斗、关卡挑战类项目。项目以即时战斗、技能释放、敌我攻防和关卡挑战为主要体验，但保留角色成长、资源奖励和后续养成扩展空间。

| 项目 | 内容 |
|---|---|
| 当前版本 | 战斗驱动基础示例 |
| 核心体验 | 操作、打击反馈、技能选择、挑战成长 |
| 单局时长 | 3-8 分钟，可调 |
| 目标用户 | 喜欢战斗反馈和成长挑战的中轻度玩家 |
| 扩展方向 | Roguelite、ARPG、动作闯关、自动战斗 RPG |

### 2. 核心体验

玩家通过进入关卡、操控角色进行战斗、击败敌人、获得奖励、提升角色能力，并挑战更高难度内容。核心体验强调“即时反馈”和“可感知成长”。

### 3. 核心循环

```text
选择关卡
→ 进入战斗
→ 击败敌人/完成目标
→ 获得资源与掉落
→ 强化角色/技能/装备
→ 解锁更高难度关卡
→ 再次挑战
```

### 4. 系统模块

#### 4.1 战斗系统

战斗系统是核心模块，负责角色移动、攻击、技能释放、受击反馈、敌人行为、胜负结算。

输入：角色属性、技能配置、敌人配置、关卡机制。  
输出：战斗结果、伤害数据、奖励结算、关卡进度。

#### 4.2 技能系统

技能系统提供不同战斗选择，包括普通攻击、主动技能、被动技能、终结技或局内成长技能。

可配置参数：技能倍率、冷却时间、消耗、范围、控制效果、触发条件。

#### 4.3 敌人系统

敌人系统用于提供挑战，包括普通敌人、精英敌人、Boss、机制型敌人。

可配置参数：生命、攻击、防御、移动速度、攻击频率、技能、AI行为。

#### 4.4 成长系统

成长系统用于承接战斗奖励，包括角色等级、技能升级、装备强化、天赋解锁等。

### 5. 数值重点

战斗驱动方向应重点关注：

1. TTK，即击败敌人所需时间。
2. 玩家容错率。
3. 技能冷却和伤害倍率。
4. 敌人攻击频率和伤害。
5. 操作收益与数值成长之间的平衡。

基础公式可采用：

```text
最终伤害 = (攻击力 × 技能倍率 + 技能基础伤害) × 防御修正 × 暴击修正
```

### 6. MVP 版本

MVP 阶段建议只实现：

1. 1 名基础角色。
2. 3 个技能。
3. 5 个关卡。
4. 3 类敌人。
5. 1 个 Boss。
6. 基础升级和奖励系统。

### 7. 风险点

| 风险 | 说明 |
|---|---|
| 战斗手感不足 | 即时反馈差会影响核心体验 |
| 数值压过操作 | 养成数值过强会削弱操作价值 |
| 难度曲线失衡 | 太难劝退，太简单无挑战 |
| 技能同质化 | 技能缺少差异会降低构筑空间 |

## 示例二：养成驱动方向游戏策划方案

### 1. 项目概述

本示例为养成驱动方向的基础游戏策划方案，适用于 RPG、卡牌、放置、收集培养类项目。项目以角色收集、资源积累、等级成长、装备强化和阶段目标为主要驱动力。

| 项目 | 内容 |
|---|---|
| 当前版本 | 养成驱动基础示例 |
| 核心体验 | 收集、培养、变强、解锁 |
| 单次时长 | 5-15 分钟，支持长期登录 |
| 目标用户 | 喜欢成长反馈和长期目标的玩家 |
| 扩展方向 | 卡牌 RPG、放置 RPG、宠物养成、队伍养成 |

### 2. 核心体验

玩家通过完成关卡、任务或挂机获得资源，用于培养角色、提升装备和解锁新内容。核心体验是“每次回来都有收益，每次投入都有成长”。

### 3. 核心循环

```text
完成任务/战斗/挂机
→ 获得经验、货币、材料
→ 培养角色、技能、装备
→ 提升战力
→ 解锁新关卡、新角色、新系统
→ 获取更高收益
```

### 4. 系统模块

#### 4.1 角色收集系统

角色作为核心养成对象，可包含稀有度、职业、定位、技能和羁绊。

#### 4.2 成长系统

成长线包括角色等级、升星、技能升级、装备强化、天赋、图鉴等。基础版本应控制成长线数量，避免早期过重。

#### 4.3 资源系统

资源包括金币、经验材料、突破材料、装备材料、抽取资源等。

#### 4.4 奖励系统

奖励来自关卡、任务、挂机、活动和成就。奖励应与成长目标直接相关。

### 5. 数值重点

养成驱动方向应重点关注：

1. 成长速度。
2. 资源产出与消耗。
3. 战力来源权重。
4. 角色稀有度差异。
5. 免费玩家与付费玩家体验边界。

成长公式示例：

```text
角色当前战力 = 基础属性战力 + 等级战力 + 装备战力 + 技能战力 + 其他加成
```

资源消耗示例：

```text
升级消耗 = 基础消耗 × 当前等级 ^ 消耗成长系数
```

### 6. MVP 版本

MVP 阶段建议实现：

1. 6-10 名角色。
2. 角色等级成长。
3. 简单技能系统。
4. 10-20 个关卡。
5. 基础资源产消。
6. 简单挂机奖励。

### 7. 风险点

| 风险 | 说明 |
|---|---|
| 成长线过多 | 玩家早期理解成本高 |
| 数值膨胀 | 后期属性失控，难以平衡 |
| 资源卡点过重 | 影响留存和体验 |
| 角色强度失衡 | 导致单一阵容或付费压制 |

## 示例三：策略驱动方向游戏策划方案

### 1. 项目概述

本示例为策略驱动方向的基础游戏策划方案，适用于回合制策略、塔防、自走棋、卡牌构筑、SLG 轻量玩法等。项目以阵容搭配、克制关系、局内决策和复盘优化为核心。

| 项目 | 内容 |
|---|---|
| 当前版本 | 策略驱动基础示例 |
| 核心体验 | 决策、搭配、克制、复盘 |
| 单局时长 | 5-15 分钟，可调 |
| 目标用户 | 喜欢思考、搭配和挑战的玩家 |
| 扩展方向 | 塔防、战棋、自走棋、卡牌构筑 |

### 2. 核心体验

玩家通过选择单位、构建阵容、利用克制关系和地图机制完成挑战。胜负不只由数值决定，更由选择、站位、顺序和组合决定。

### 3. 核心循环

```text
查看挑战目标
→ 配置单位/卡组/阵容
→ 进入对局
→ 根据局势做出决策
→ 获得胜负结果与奖励
→ 调整阵容和策略
→ 挑战更复杂内容
```

### 4. 系统模块

#### 4.1 单位系统

单位拥有职业、阵营、费用、属性、技能和克制关系。

#### 4.2 阵容系统

玩家可根据关卡目标组合不同单位。阵容应存在多种可行解，而不是唯一最优解。

#### 4.3 克制系统

可采用属性克制、职业克制、攻击类型克制或机制克制。

#### 4.4 关卡系统

关卡应提供差异化目标，例如防守、突袭、护送、限时、资源限制等。

### 5. 数值重点

策略方向应重点关注：

1. 单位成本与收益。
2. 克制倍率。
3. 技能效果强度。
4. 阵容组合收益。
5. 失败后的可复盘性。

克制公式示例：

```text
最终伤害 = 基础伤害 × 克制倍率 × 技能修正 × 防御修正
```

单位价值评估：

```text
单位价值 = 基础属性价值 + 技能价值 + 克制价值 + 阵容协同价值
```

### 6. MVP 版本

MVP 阶段建议实现：

1. 8-12 个单位。
2. 3 类职业。
3. 2-3 种克制关系。
4. 10 个策略关卡。
5. 基础阵容编辑。
6. 对局结算和奖励。

### 7. 风险点

| 风险 | 说明 |
|---|---|
| 单一最优解 | 降低策略空间 |
| 学习成本过高 | 新手难以上手 |
| 数值压制策略 | 策略选择失去意义 |
| 平衡成本高 | 多单位、多组合容易失衡 |

| 项目 | 内容 |

### 2. 核心体验

玩家快速进入关卡，通过简单操作完成目标，获得奖励、解锁新关卡或道具。核心体验强调“低门槛”和“即时反馈”。

#### 4.3 奖励系统

#### 4.4 轻成长系统

### 5. 数值重点

休闲方向应重点关注：

1. 单局时长。
2. 失败率。
3. 道具消耗率。
4. 关卡通关率。
5. 奖励反馈频率。

关卡难度可由以下参数控制：

|---|---|
| 玩法单薄 | 内容消耗过快 |
| 难度突变 | 轻度玩家容易流失 |

## 示例五：经营模拟方向游戏策划方案

### 1. 项目概述

本示例为经营模拟方向的基础游戏策划方案，适用于店铺经营、农场、工厂、城市建设、放置经营等。项目以生产资源、完成订单、升级设施、扩大规模为核心。

| 项目 | 内容 |
|---|---|
| 当前版本 | 经营模拟基础示例 |
| 核心体验 | 生产、建设、扩张、效率提升 |
| 单次时长 | 5-10 分钟，支持挂机收益 |
| 目标用户 | 喜欢规划、收集、建设和长期成长的玩家 |
| 扩展方向 | 店铺、农场、工厂、城市、基地建设 |

### 2. 核心体验

玩家通过建造生产设施、安排员工或资源、生产商品、完成订单、获得收益，并继续升级设施和扩大经营范围。

### 3. 核心循环

```text
生产资源/商品
→ 完成订单/出售商品
→ 获得货币和材料
→ 升级建筑/员工/产线
→ 解锁新商品和新区域
→ 提高生产效率
```

### 4. 系统模块

#### 4.1 生产系统

生产系统负责将原料转化为商品，或将时间转化为收益。

#### 4.2 建筑系统

建筑提供生产、存储、加工、销售、装饰或功能加成。

#### 4.3 员工系统

员工可提供效率加成、自动化、特殊技能或产线管理。

#### 4.4 订单系统

订单用于提供目标和奖励，可分为普通订单、限时订单、稀有订单、剧情订单。

#### 4.5 资源系统

经营方向的资源系统是核心，包括原料、商品、货币、体力、容量、时间等。

### 5. 数值重点

经营方向应重点关注：

1. 生产时间。
2. 生产成本。
3. 商品售价。
4. 建筑升级成本。
5. 回本周期。
6. 离线收益。

生产公式示例：

```text
单位时间收益 = 商品售价 × 生产数量 × 效率倍率 - 原料成本
```

回本周期示例：

```text
回本时间 = 建筑升级成本 / 升级后新增单位时间收益
```

### 6. MVP 版本

MVP 阶段建议实现：

1. 3 类资源。
2. 3-5 个建筑。
3. 5-10 种商品。
4. 10-20 个订单。
5. 基础升级系统。
6. 简单离线收益。

### 7. 风险点

| 风险 | 说明 |
|---|---|
| 等待时间过长 | 玩家无事可做 |
| 经济失衡 | 收益过高或升级过贵 |
| 目标感不足 | 玩家不知道下一步做什么 |
| 生产链过复杂 | 早期理解成本高 |

# 第十一部分：工业级主题写作要点

本部分覆盖工业级游戏策划案中容易缺失的专业主题，包括商业化指标、风险管理、MVP 验证、市场分析、AI 行为、教程设计、无障碍设计、项目管理、营销计划和运营计划。这些主题是项目立项和融资决策的关键依据，必须用数据说话，不能停留在定性描述。

## 11.1 商业化指标写作

### 核心指标定义

| 指标 | 定义 | 计算公式 |
|------|------|----------|
| LTV | 生命周期价值 | LTV = ARPU × 生命周期天数 |
| CAC | 获客成本 | CAC = 总营销费用 / 新增用户数 |
| ARPU | 每用户平均收入 | ARPU = 总收入 / 活跃用户数 |
| ARPPU | 每付费用户平均收入 | ARPPU = 总收入 / 付费用户数 |
| 付费渗透率 | 付费用户占比 | 付费渗透率 = 付费用户数 / 活跃用户数 |
| ROI | 投资回报率 | ROI = (LTV - CAC) / CAC |

### 写作规范

1. **LTV/CAC 必须成对出现**：单独写 LTV 或 CAC 没有意义，必须同时给出并计算比值。健康标准：LTV/CAC ≥ 3。
2. **付费分层必须覆盖 4 类用户**：大R（鲸鱼）、中R（海豚）、小R（小鱼）、免费用户。占比合计 100%，每类标注 ARPU 目标。
3. **行业基准参考**：F2P 游戏付费渗透率 2-5% 为及格，8-15% 为优秀；次日留存 40% 为及格，七日留存 15% 为及格。
4. **付费路径是阶梯**：从免费 → 首充 → 月卡 → 战令 → 重氪，每级都要让玩家觉得比上一级值。

### 示例

```text
LTV 目标：180 元（90 天生命周期，ARPU 2 元/天）
CAC 目标：30 元
LTV/CAC = 6 > 3，健康

付费用户分层：
- 大R(鲸鱼)：占比 2%，ARPU 5000 元/月
- 中R(海豚)：占比 8%，ARPU 500 元/月
- 小R(小鱼)：占比 20%，ARPU 50 元/月
- 免费用户：占比 70%，ARPU 0 元
付费渗透率目标：30%
```

## 11.2 风险管理写作

### 8 大风险维度

| 维度 | 典型风险 | 关键指标 |
|------|----------|----------|
| 技术风险 | 引擎性能不达标、核心技术无法实现 | 帧率、内存、加载时间 |
| 设计风险 | 核心玩法循环无法支撑长线留存 | 七日留存、重复游玩率 |
| 市场风险 | 竞品提前上线、用户偏好变化 | 竞品动态、市场趋势 |
| 团队风险 | 核心成员流失、招聘困难 | 离职率、到岗时间 |
| 时间风险 | 里程碑延期、错过上线窗口 | 延期天数、缓冲消耗 |
| 法律风险 | IP 侵权、版号问题、合规要求 | 法务审查状态 |
| 资金风险 | 预算超支、融资不到位 | 月度支出/预算比 |
| 运营风险 | 外挂刷分、舆论危机、服务器故障 | 举报量、舆情指数 |

### 概率影响矩阵

每个风险必须填写概率（高/中/低）和影响（高/中/低），用于生成风险矩阵：

| 概率＼影响 | 高影响 | 中影响 | 低影响 |
|------------|--------|--------|--------|
| 高概率 | 🔴 优先处理 | 🔴 优先处理 | 🟡 监控 |
| 中概率 | 🔴 优先处理 | 🟡 监控 | 🟢 接受 |
| 低概率 | 🟡 监控 | 🟢 接受 | 🟢 接受 |

### 写作规范

1. 每个风险必须归类到 8 大维度之一，使用枚举值。
2. 概率和影响使用枚举（高/中/低），不用自由文本。
3. 每个风险必须有缓解方案（降低概率或影响）和应急预案（风险发生后的应对）。
4. 必须标注触发条件（什么情况下风险会触发）和负责人。
5. 风险状态使用枚举：已缓解/监控中/已发生/已关闭。

## 11.3 MVP 验证写作

### 核心要素

MVP 不是简化版，是验证版。必须包含以下要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| 核心假设 | MVP 要验证的最关键问题 | "玩家是否愿意为轻量化开放世界重复战斗 10 次以上" |
| 成功 KPI | 量化成功标准 | 次日留存 30%、平均时长 8 分钟、重复游玩率 40% |
| 失败标准 | 量化失败标准 | 次日留存<20% 或 重复游玩率<20% 则验证失败 |
| 验证方法 | 如何收集数据 | 用户测试(10人) + A/B测试(2组) + 数据埋点 |
| 开发工时 | 估算开发周期 | 核心循环 2周 + 1关卡 1周 + 1角色 1周 = 4周 |
| 资源需求 | 人力和工具 | 1策划+2程序+1美术，4周开发周期 |

### 写作规范

1. **核心假设必须是一个可验证的问题**，通常以"玩家是否愿意..."开头。
2. **KPI 必须量化**，不能是"留存好"这种定性描述。
3. **必须同时定义成功标准和失败标准**，失败标准明确什么情况下需要调整方向或放弃。
4. **MVP 范围能在一周内完成原型验证**，只列验证核心循环必需的项。

## 11.4 市场分析写作

### 核心要素

| 要素 | 说明 | 数据来源 |
|------|------|----------|
| 目标市场规模 | 细分品类的市场规模和增长率 | Newzoo/Sensor Tower/伽马数据 |
| 竞品分析 | 至少 3 款竞品的优劣势分析 | App Annie/七麦/玩家评论 |
| 差异化定位 | 明确"我们比竞品好在哪" | 竞品对比分析 |
| 市场趋势 | 细分品类的趋势判断 | 行业报告/数据 |
| 市场定位 | 一句话说清定位 | 综合 |

### 写作规范

1. **竞品分析至少 3 款**，覆盖成功和失败案例，标注竞品类型（直接/间接/潜在）。
2. **每个竞品必须给出创新度评分和完成度评分**（0-10 分），并标注"借鉴/规避"。
3. **差异化定位必须具体**：明确说出与每个竞品的差异点，而非泛泛的"我们有创新"。
4. **市场趋势要基于数据**，标注数据来源和年份，不要凭感觉。

## 11.5 AI 行为写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 状态机定义 | AI 的状态、转移条件、行为输出 | IDLE→PATROL→CHASE→ATTACK→FLEE |
| 难度分级 | 各难度的参数差异倍率 | 简单×0.8 / 普通×1.0 / 困难×1.5 |
| 性能预算 | 同屏 AI 上限、决策频率、LOD 策略 | 同屏≤20，决策频率 10Hz，远距离降频 |

### 写作规范

1. **状态机必须用枚举值**：状态名使用大写英文枚举（IDLE/PATROL/CHASE/ATTACK/FLEE/DEAD），不用自由文本。转移条件必须是可量化事件（距离、血量、时间、视野），不用"适当时候"。
2. **难度分级用倍率表**：每个难度标注血量、攻击、反应时间、决策频率的倍率，不用绝对值。倍率表便于全局调整。
3. **性能预算可测试**：标注同屏 AI 上限、每帧决策预算（ms）、LOD 策略（远距离降频/冻结/简化逻辑）。性能预算必须接入性能监控。

## 11.6 教程设计写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 教学流程 | 教学步骤序列、每步目标、时长 | 移动教学(15s)→战斗教学(30s)→养成教学(20s) |
| 触发条件 | 基于 event+condition 的触发规则 | 玩家进入主城 AND 未完成移动教学 → 触发 |
| 失败容错 | 卡住时的兜底策略 | 30s 未完成 → NPC 示范 → 跳过选项 |

### 写作规范

1. **教学步骤四段式**：操作示范→引导尝试→独立完成→强化反馈。每步标注目标、输入、反馈、时长。
2. **触发条件可量化**：使用"事件+条件→动作"格式，避免模糊表述。触发条件必须可测试。
3. **失败容错必须有兜底**：定义失败判定（超时/错误次数），提供跳过选项，跳过后补发教学奖励。

## 11.7 无障碍设计写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 色盲支持 | 色觉适配、形状辅助、色彩可调 | 红绿色盲：血条增加三角形/圆形标识 |
| 字幕支持 | 对话字幕、音效字幕、样式可调 | 所有语音配字幕，音效标注"[爆炸声]" |
| 运动辅助 | 按键重映射、操作辅助、暂停模式 | 自动瞄准、QTE 自动完成、慢速模式 |

### 写作规范

1. **色盲支持要列出依赖颜色的元素**：标注哪些游戏元素依赖颜色区分（血条、阵营、稀有度），并提供形状/图标辅助方案。
2. **字幕覆盖所有语音**：对话字幕标注显示时长（按字数计算），音效字幕标注音效类型。字幕样式可调（字号、颜色、背景）。
3. **运动辅助标注影响范围**：每项辅助标注是否影响成就/排行，避免辅助功能被滥用。

## 11.8 项目管理写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 里程碑 | 阶段名称、时间节点、交付物、验收标准 | Alpha(2026-09)：核心玩法可玩 |
| 团队配置 | 岗位、人数、职责、到岗时间 | 1 主策+2 策划+3 程序+2 美术 |
| 预算估算 | 人力、工具、营销、缓冲 | 人力 200 万+工具 20 万+缓冲 40 万 |

### 写作规范

1. **里程碑必须有可验证的交付标准**：每个里程碑标注交付物清单和验收标准，不用"基本完成"等模糊表述。
2. **团队配置标注 AB 角**：关键岗位（主程、主策、主美）必须有 AB 角配置，降低人员风险。
3. **预算预留 15-20% 缓冲**：缓冲预算应对风险和变更，预算与里程碑挂钩分阶段释放。

## 11.9 营销计划写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 渠道策略 | 自有/付费/社媒/KOL 渠道 | 抖音信息流：CAC 15 元，15s 竖版视频 |
| KPI 设定 | 曝光/点击/转化/留存/变现分层 | CAC≤30 元，LTV/CAC≥3 |
| 预算分配 | 各渠道占比、分阶段投放 | 买量 60%+KOL 20%+社媒 10%+缓冲 10% |

### 写作规范

1. **渠道标注用户匹配度和 CAC 预估**：每个渠道标注目标用户匹配度（高/中/低）、CAC 预估、内容形式要求。
2. **KPI 分层且量化**：曝光层（CPM）、点击层（CPC）、转化层（CAC）、留存层（次日/七日留存）、变现层（LTV/ROI），每层标注目标值和行业基准。
3. **预算分配与 KPI 挂钩**：定期复盘各渠道 ROI，调整预算分配。缓冲预算≥10%。

## 11.10 运营计划写作

### 核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 赛季规划 | 周期、主题、新增内容、奖励 | S1(4 周)：暗影降临，2 角色+10 关卡 |
| 活动规划 | 类型、节奏、目标、奖励 | 节日/联动/限时挑战/福利，每周≥1 个 |
| 内容路线图 | 6-12 个月更新计划 | M+1 公会系统，M+3 PVP 玩法 |

### 写作规范

1. **赛季规划标注 KPI 影响**：每个赛季标注预期 DAU 提升、付费提升，不用"应该会好"。
2. **活动节奏避免冲突**：保持每周至少 1 个活跃活动，活动时间窗口不重叠。每个活动标注开发工时。
3. **内容路线图保留弹性**：按月/季度列出更新计划，根据数据反馈调整优先级。路线图不是承诺，是方向。

# 第十二部分：好坏示例对比

本部分通过"❌ 错误写法 vs ✅ 正确写法"对比，展示工业级主题的写作标准。

## 12.1 市场分析对比

### ❌ 错误写法

```text
竞品分析：
原神很火，我们也想做开放世界。幻塔做得一般，我们可以做得更好。
我们有创新，玩法独特，相信能获得玩家喜爱。

差异化定位：
我们的游戏比竞品更好玩，画面更精美，玩法更丰富。
```

**问题**：没有数据支撑、没有具体差异点、"更好玩"无法验证。

### ✅ 正确写法

```text
竞品分析：
1. 原神（直接竞品）：优势=开放世界+角色塑造+音乐；劣势=肝度高、移动端体验差；
   创新度 9/10，完成度 10/10；借鉴=角色塑造手法，规避=过重日常。
2. 幻塔（直接竞品）：优势=战斗手感+捏脸系统；劣势=剧情薄弱、优化差；
   创新度 6/10，完成度 7/10；借鉴=战斗手感，规避=剧情投入。
3. 鸣潮（直接竞品）：优势=战斗系统+声骸玩法；劣势=内容消耗快；
   创新度 7/10，完成度 8/10；借鉴=声骸收集，规避=内容节奏。

差异化定位：
我们与原神的差异在于轻量化开放世界，单局时长控制在 5 分钟内，
适合移动端碎片时间；与幻塔的差异在于剧情投入更深，
世界观有不可调和的核心冲突驱动。
```

## 12.2 MVP 验证对比

### ❌ 错误写法

```text
MVP 范围：
做一个简化版的游戏，包含基本功能，看看玩家喜不喜欢。

成功标准：
玩家觉得好玩，留存不错。
```

**问题**：范围模糊、"简化版"不是验证版、成功标准无法量化。

### ✅ 正确写法

```text
MVP 范围：
1 名基础角色 + 3 个技能 + 5 个关卡 + 3 类敌人 + 1 个 Boss + 基础升级和奖励系统。
不包含：社交系统、付费系统、多角色切换、装备系统。

核心验证假设：
玩家是否愿意为"轻量化开放世界+二次元"重复战斗 10 次以上。

成功 KPI：
- 次日留存 ≥ 30%
- 平均单次时长 ≥ 8 分钟
- 重复游玩率（同一玩家 24 小时内再次进入）≥ 40%

失败标准：
- 次日留存 < 20%，或
- 重复游玩率 < 20%
则验证失败，需调整核心玩法或放弃方向。

验证方法：
用户测试(10 人) + A/B 测试(2 组) + 数据埋点（登录、进入关卡、完成关卡、流失节点）
```

## 12.3 风险管理对比

### ❌ 错误写法

```text
风险：
有技术风险，可能性能不达标。
有市场风险，竞品可能比我们先上线。
团队也有风险，可能有人离职。
```

**问题**：没有分类、没有概率影响评估、没有缓解方案和应急预案。

### ✅ 正确写法

```text
风险清单：
1. 技术风险：引擎性能不达标，无法支撑开放世界
   概率：中 | 影响：高 | 负责人：技术总监
   缓解方案：早期性能压测，准备降级方案
   应急预案：缩小地图规模或切换引擎
   触发条件：帧率<30fps 或内存>2GB
   状态：监控中

2. 市场风险：竞品提前上线，抢占目标用户
   概率：中 | 影响：高 | 负责人：制作人
   缓解方案：关注竞品动态，准备差异化策略
   应急预案：调整上线时间或差异化卖点
   触发条件：同类产品上线
   状态：监控中

3. 团队风险：核心成员流失
   概率：低 | 影响：高 | 负责人：制作人
   缓解方案：知识共享、文档沉淀、股权激励
   应急预案：启动招聘，关键岗位 AB 角
   触发条件：核心成员提出离职
   状态：监控中
```

## 12.4 商业化指标对比

### ❌ 错误写法

```text
商业化：
做 F2P，靠抽卡赚钱。玩家应该会付费，因为我们游戏好玩。
```

**问题**：没有 LTV/CAC 测算、没有付费分层、没有量化目标。

### ✅ 正确写法

```text
付费模式：F2P+混合（外观+战力）

LTV 目标：180 元（90 天生命周期，ARPU 2 元/天）
CAC 目标：30 元
LTV/CAC = 6 > 3，健康
付费渗透率目标：8%（优秀产品基准）

付费用户分层：
- 大R(鲸鱼)：占比 2%，ARPU 5000 元/月，策略=限定皮肤+赛季排行
- 中R(海豚)：占比 8%，ARPU 500 元/月，策略=月卡+通行证
- 小R(小鱼)：占比 20%，ARPU 50 元/月，策略=首充礼包+月卡
- 免费用户：占比 70%，ARPU 0 元，策略=广告变现+活跃奖励

不卖什么：核心战力、PVP 优势、剧情解锁
```

## 12.5 项目管理对比

### ❌ 错误写法

```text
项目管理：
团队有 10 个人，预计 6 个月做完。
预算大概 200 万左右。
里程碑：先做原型，再做 Alpha，然后 Beta，最后上线。
```

**问题**：里程碑没有时间节点和交付物、团队配置没有岗位分工、预算没有分类拆解、没有缓冲预算。

### ✅ 正确写法

```text
里程碑：
1. 原型（2026-07-15）：核心循环可玩
   交付物：1 关卡+1 角色+战斗系统
   验收标准：核心循环跑通，帧率≥30fps
   依赖：战斗系统开发完成
2. Alpha（2026-09-01）：核心玩法完整
   交付物：5 关卡+3 角色+养成系统+UI 框架
   验收标准：核心玩法 30 分钟体验完整
3. Beta（2026-11-01）：内容量达标
   交付物：20 关卡+10 角色+全系统+付费系统
   验收标准：全功能可玩，bug≤50
4. 上线（2026-12-15）：正式发布
   交付物：上线包+运营工具+数据看板
   验收标准：通过平台审核，性能达标

团队配置：
- 主策 A：张三（到岗 2026-06-01），B：李四（2026-07-01）
- 策划×2：王五、赵六（2026-06-15 到岗）
- 主程 A：钱七（到岗 2026-06-01），B：孙八（2026-07-01）
- 程序×3：周九、吴十、郑十一（2026-06-15 到岗）
- 主美 A：王十二（到岗 2026-06-01）
- 美术×2：冯十三、陈十四（2026-06-15 到岗）

预算估算：
- 人力成本：10 人×2 万/月×6 月 = 120 万
- 工具/服务：引擎授权 10 万+服务器 5 万+测试设备 5 万 = 20 万
- 营销成本：50 万（详见营销计划）
- 缓冲预算：38 万（占比 16%，应对风险和变更）
- 总预算：228 万
```

## 12.6 运营计划对比

### ❌ 错误写法

```text
运营计划：
上线后每个月更新一次内容。
偶尔搞点活动，发点福利。
赛季大概 1 个月一个，给点奖励。
```

**问题**：没有具体时间节点、没有 KPI 目标、没有内容量规划、活动节奏不明确。

### ✅ 正确写法

```text
赛季规划：
- S1（上线第 1-4 周）：主题=暗影降临
  新增：2 角色+10 关卡+1 Boss
  奖励：限定皮肤+赛季通行证（免费/付费）
  KPI 目标：DAU+15%，付费渗透率+5%
- S2（上线第 5-8 周）：主题=光明觉醒
  新增：1 角色+10 关卡+公会系统
  奖励：赛季专属头像框+通行证
  KPI 目标：七日留存+3%，ARPU+10%

活动规划：
- 上线首周：登录福利活动（目标=促活，奖励=每日登录礼包）
- 第 2 周：限时挑战活动（目标=变现，奖励=稀有角色碎片）
- 第 3 周：联动活动（目标=拉新，奖励=联动限定皮肤）
- 第 4 周：赛季结算活动（目标=回流，奖励=赛季排名奖励）
- 节奏：每周≥1 个活跃活动，活动时间窗口不重叠

内容路线图：
- M+1（v1.1）：新增公会系统，预期 DAU+10%
- M+2（v1.2）：新增 PVP 竞技场，预期留存+5%
- M+3（v1.3）：新增第 2 章节剧情，预期内容消耗+20%
- M+6（v2.0）：大型资料片，新增职业系统+新地图
```

# 结语

本指南的核心价值在于：先建立一套能让真人和 LLM 都理解的游戏策划案写作结构，再基于模块化系统和数值骨架扩展到不同玩法方向。对于早期项目，不应追求一次性写成最终完整大案，而应先确保核心循环清晰、系统关系明确、数值框架可调、玩法方向可扩展。
